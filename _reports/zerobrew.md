# **zerobrew 調査レポート**

## **1. 基本情報**

* **ツール名**: zerobrew
* **ツールの読み方**: ゼロブリュー
* **開発元**: zerobrewhq (旧 lucasgelfond)
* **公式サイト**: [https://zerobrew.rs/](https://zerobrew.rs/)
* **関連リンク**:
  * GitHub: [https://github.com/zerobrewhq/zerobrew](https://github.com/zerobrewhq/zerobrew)
* **カテゴリ**: パッケージマネージャー
* **概要**: macOSおよびLinux向けの、uvスタイルのアーキテクチャを採用したHomebrewの代替クライアント。Homebrewのインフラを活用しつつ、最大100倍高速なインストールを実現している。

## **2. 目的と主な利用シーン**

* **解決する課題**: Homebrewのパッケージインストールにおける遅さ（Rubyランタイムの起動、直列ダウンロード、インストールごとのリンク処理など）を解消し、高速な環境構築を可能にする。
* **想定利用者**:
  * パッケージインストールの待ち時間を短縮したい開発者
  * 頻繁に環境構築を行うエンジニア
  * macOSやLinuxのCLIユーザー
* **利用シーン**:
  * 新しいmacOS環境のセットアップ
  * 開発ツールの迅速なインストールやアップグレード
  * CI/CD環境でのパッケージ依存関係の高速な解決とインストール

## **3. 主要機能**

* **超高速インストール**: コンテンツアドレッサブルストレージからのリンクやAPFS clonefileを活用し、Homebrewより圧倒的に高速なインストールを実現する。
* **Homebrewとの互換性**: Homebrewのformula定義やビルド済みボトルをそのまま利用し、Homebrewで提供されているパッケージをインストールできる。
* **依存関係の解決**: 必要な依存関係を自動的に解析し、必要なパッケージのみをインストールする。
* **ダンプ/リストア機能**: `Brewfile`を利用して、現在のインストール状況をダンプしたり、ファイルから一括インストールしたりできる。
* **ソースビルドフォールバック**: ボトルがない場合は、HomebrewのRuby DSLを使用してソースからビルドするフォールバック機能を持つ。
* **自己診断・修復 (`doctor`)**: ローカルの状態を診断し、孤立したストアエントリや壊れたシンボリックリンクなどを修復する。

## **4. 動作原理・システム構成**

* **アーキテクチャ**: ローカルファーストのCLIツール。Homebrewエコシステム（ボトルビルドファームやFormula）のクライアントとして動作する。
* **主要コンポーネントとデータフロー**:
  * ダウンロードしたボトルは、コンテンツアドレッサブルストアに展開・保存される。
  * インストール時は、ストアからインストール先（Cellar）へ展開する。
  * ボトルを展開する際、Mach-Oヘッダーの書き換えなどの再配置（Relocation）をRustプロセス内でインプロセス処理し、効率的にリンクを作成する。
* **特筆すべき要素技術**:
  * **Rust**: 高速な処理と安全性を提供。
  * **コンテンツアドレッサブルストレージ (CAS)**: SHA256ハッシュを利用してボトルを重複排除し、キャッシュからの再インストールを高速化。
  * **APFS Clonefile (macOS)**: オーバーヘッドなしでのコピーを実現する。
  * **インプロセス再配置**: 外部コマンド(`otool`, `install_name_tool`)を呼び出さず、バイナリのパス書き換えを内部で処理。

## **5. 開始手順・セットアップ**

* **前提条件**:
  * macOSまたはLinux環境
* **インストール/導入**:

  ```bash
  # スタンドアロンインストーラーを利用
  curl -fsSL https://zerobrew.rs/install | bash

  # または Homebrew 経由でインストール
  brew install zerobrewhq/zerobrew/zerobrew
  ```

* **初期設定**:
  * インストーラーがシェルの設定（PATH等）を自動的に更新する。完了後、ターミナルを再起動するか表示された `source` コマンドを実行する。
* **クイックスタート**:

  ```bash
  zb install jq                   # 単一パッケージのインストール
  zb install wget git             # 複数パッケージのインストール
  zbx jq --version                # リンクせずに実行
  zb outdated                     # 古いパッケージのリスト表示
  zb upgrade                      # 全パッケージのアップグレード
  ```

## **6. 特徴・強み (Pros)**

* **圧倒的なスピード**: Homebrewと比較して、コールドインストールで数倍、ウォームキャッシュからのインストールでは最大100倍以上の高速化を実現している。
* **Homebrewエコシステムの活用**: Homebrewの膨大なボトルファームとFormulaを利用するため、パッケージの網羅性が高い。
* **並列処理**: ダウンロードや展開を並列で行うため、依存関係が多いパッケージのインストールが特に速い。
* **モダンな設計**: Pythonの`uv`にインスパイアされた、キャッシュの重複排除や並列処理など、現代的なパッケージマネージャーの設計を取り入れている。

## **7. 弱み・注意点 (Cons)**

* **実験的なプロジェクト**: 公式には「実験的」と位置付けられており、Homebrewを完全に削除して置き換えることは推奨されていない（併用が推奨）。
* **複雑なFormulaのサポート制限**: Turing完全なRubyで書かれたFormulaのすべての機能（複雑な条件分岐など）をパースできるわけではない。
* **日本語対応**: CLIや公式ドキュメントは英語が中心（ただしREADMEには有志による中国語翻訳などがある）。

## **14. ベストプラクティス**

* **効果的な活用法 (Modern Practices)**:
  * Homebrewと併用し、高速にインストールしたい一般的なパッケージ（CLIツールなど）は `zb install` で行い、複雑なCaskや固有のRubyフックが必要なものは `brew` を使うという棲み分けが推奨される。
  * CI環境などで、初回セットアップを劇的に高速化するために活用する。
* **陥りやすい罠 (Antipatterns)**:
  * Homebrewを完全に削除してしまうこと。zerobrewはHomebrewの機能に一部依存（フォールバック時など）しており、完全な代替とはまだ言えない。

## **18. 総評**

* **総合的な評価**:
  zerobrewは、Homebrewの「遅さ」という最大のペインポイントを、Rustによるモダンなアーキテクチャ（並列処理、CAS、インプロセスでのリンク処理など）で解決しようとする非常に野心的なプロジェクトである。既存のHomebrewのインフラ（ボトルファーム）にフリーライドしつつ、高速なクライアントとして振る舞うアプローチは合理的であり、実際にベンチマークでも数十倍の高速化を叩き出している。
* **推奨されるチームやプロジェクト**:
  * 頻繁に環境を構築する開発者やインフラエンジニア
  * CIパイプラインなどで環境構築の待ち時間を短縮したいプロジェクト
* **選択時のポイント**:
  現状は「実験的」なツールであるため、既存のHomebrew環境を完全に破壊して移行するのではなく、CLIツールの高速なインストールにはzerobrewを使い、複雑な依存やCaskなどはHomebrewを使うといったハイブリッドな利用が推奨される。同じアプローチをとる`nanobrew`と比較して、どちらのエコシステムがより早く安定するかを注視したい。
