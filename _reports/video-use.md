# **video-use 調査レポート**

## **1. 基本情報**

* **ツール名**: video-use
* **ツールの読み方**: ビデオユース
* **開発元**: Browser Use
* **公式サイト**: [https://github.com/browser-use/video-use](https://github.com/browser-use/video-use)
* **関連リンク**:
  * GitHub: [https://github.com/browser-use/video-use](https://github.com/browser-use/video-use)
* **カテゴリ**: AI開発者ツール
* **概要**: video-useは、Claude CodeやCodexなどのAIコーディングエージェントを使用して動画を編集できる100%オープンソースのツールです。生データをフォルダにドロップし、エージェントとチャットするだけで、不要な言葉のカット、カラーグレーディング、字幕追加、アニメーション生成などを自動で行い、完成した動画を出力します。

## **2. 目的と主な利用シーン**

* **解決する課題**: 複雑な動画編集ソフトウェアの学習コストや、細かいカット作業、字幕付けにかかる膨大な時間を削減し、自然言語の指示のみでプロフェッショナルな動画編集を実現する。
* **想定利用者**: 開発者、コンテンツクリエイター、マーケター
* **利用シーン**:
  * トーキングヘッド動画、チュートリアル、インタビュー動画の自動カットと字幕付与
  * 複数のテイクから最適な部分を抽出してまとめたプロモーション動画の作成
  * アニメーションや図解（Manim、Remotion等）をオーバーレイした解説動画の制作

## **3. 主要機能**

* **スマートカット機能**: 「えー」「あの」などのフィラーワード（無意味な言葉）や、テイク間の無音部分を自動的にカットします。
* **自動カラーグレーディング**: 映像の各セグメントに対して、シネマティックな暖色系やニュートラルな補正など、FFmpegベースのカスタムフィルターチェーンを適用します。
* **オーディオフェードの自動適用**: 全てのカット境界に30msのオーディオフェードを挿入し、音声のポップノイズを防ぎます。
* **カスタム字幕の焼き付け**: デフォルトで2単語ごとの大文字チャンクなど、スタイルを完全にカスタマイズ可能な字幕を動画に合成します。
* **アニメーション生成とオーバーレイ**: HyperFrames、Remotion、Manim、PILなどを活用し、それぞれ並列のサブエージェントでアニメーションを生成し、映像にオーバーレイします。
* **セルフエバリュエーション（自己評価）**: 出力された映像をユーザーに提示する前に、各カット境界で自己評価ループ（ジャンプカットやポップノイズ、字幕の隠れなどのチェック）を実行します。
* **セッションメモリ機能**: 編集内容を `project.md` に保存し、次回のセッションでも前回の作業の続きから再開できます。

## **4. 動作原理・システム構成**

* **アーキテクチャ**: ローカルファーストのクライアントベース（各種AIエージェントのスキルとして動作）
* **主要コンポーネントとデータフロー**:
  * LLM（Claude等）は映像自体を直接「見る」わけではなく、テキストトランスクリプトを通じて映像を「読み」ます。
  * **Layer 1 (Audio transcript)**: ElevenLabs API（Scribe）を利用して、音声から単語レベルのタイムスタンプ、話者分離、音声イベント（笑い声、拍手など）を含む詳細なトランスクリプトを生成します。これを約12KBの `takes_packed.md` に圧縮してLLMに読み込ませます。
  * **Layer 2 (Visual composite)**: 必要に応じて `timeline_view` を使用し、フィルムストリップ、話者のトラッキング、波形、単語ラベルを含むPNG画像を生成してLLMに分析させます。
  * **パイプライン**: `Transcribe` → `Pack` → `LLM Reasons` → `EDL (Edit Decision List) 作成` → `Render` → `Self-Eval (問題があれば最大3回修正・再レンダリング)` のフローで動作します。
* **特筆すべき要素技術**:
  * **FFmpeg**: 映像のカット、カラーグレーディング、音声フェード、最終的な合成などのコア処理に使用されます。
  * **ElevenLabs API**: 高精度な文字起こしとタイムスタンプ取得に使用されます。

## **5. 開始手順・セットアップ**

* **前提条件**:
  * 任意のAIエージェント（Claude Code, Codex, Hermes等）
  * FFmpegのインストール
  * ElevenLabs APIキー
  * (オプション) yt-dlp, Node.js (HyperFrames/Remotion使用時)
* **インストール/導入**:

  ```bash
  # 1. リポジトリのクローンとエージェントのskillsディレクトリへのシンボリックリンク作成
  git clone https://github.com/browser-use/video-use ~/Developer/video-use
  ln -sfn ~/Developer/video-use ~/.claude/skills/video-use  # Claude Codeの場合

  # 2. 依存関係のインストール
  cd ~/Developer/video-use
  uv sync  # または pip install -e .
  brew install ffmpeg
  ```

* **初期設定**:
  * リポジトリのルートに `.env` ファイルを作成し、`ELEVENLABS_API_KEY=...` を設定します。
* **クイックスタート**:
  * 動画ファイルのあるディレクトリに移動し、エージェントを起動します。
  * エージェントに `Set up https://github.com/browser-use/video-use for me.` と指示し、その後 `edit these into a launch video` のように指示します。

## **6. 特徴・強み (Pros)**

* AIエージェントとの対話だけで、プロ水準のカット、カラーグレーディング、字幕追加が完了する。
* 映像全体をAIに解析させるのではなく、音声テキスト（トランスクリプト）とポイントごとの画像を解析させることで、トークン数を大幅に節約し効率的に処理する。
* 自己評価ループにより、カット時の映像の乱れや音声のノイズをAI自身が検知して修正する。
* オープンソースであるため、開発者が自由にスクリプト（Python, FFmpegコマンド）をカスタマイズできる。

## **7. 弱み・注意点 (Cons)**

* コマンドライン操作や環境構築（FFmpeg、Python、各種ライブラリのインストール）が必要なため、非エンジニアには導入ハードルが高い。
* 文字起こしにElevenLabs APIを使用するため、利用量に応じたAPIの従量課金が発生する。
* トランスクリプト（文字起こし）の精度に編集の質が大きく依存する。日本語の文字起こしやテロップの品質はElevenLabsの日本語対応精度に依存する。

## **12. セキュリティとコンプライアンス**

* **認証**: ツール自体の認証機能はありません。ElevenLabsなどの外部APIは、ローカルの `.env` または環境変数でAPIキーを管理します。
* **データ管理**: 動画データはローカルマシンの作業ディレクトリ（`<videos_dir>/edit/`）に保存され、クラウドには送信されません（文字起こしのために音声データはElevenLabsに送信されます）。
* **準拠規格**: オープンソースソフトウェアのため、特定のコンプライアンス認証は取得していません。

## **13. 操作性 (UI/UX) と学習コスト**

* **UI/UX**: GUIは存在せず、AIエージェントのCLI（コマンドラインインターフェース）を通じたチャットベースの操作となります。自然言語で指示を出せるため、エージェントを通じた操作自体は直感的です。
* **学習コスト**: 動画編集自体の学習コストは皆無ですが、初回セットアップ（GitHubからのクローン、環境変数の設定、AIエージェントの導入）に開発者向けの知識が必要です。

## **14. ベストプラクティス**

* **効果的な活用法 (Modern Practices)**:
  * 編集前にエージェントに「戦略を提案して」と指示し、AIが生成した編集方針（カットの方向性、アニメーションの計画など）を確認してから実行に移すこと。
  * 複数のテイクがある場合、`transcribe_batch.py` を使って一括でトランスクリプトを生成し、最適なテイクをLLMに選択させる。
* **陥りやすい罠 (Antipatterns)**:
  * 音声の単語途中でのカット。必ずスクリプト（Scribe）の境界でカットを行う（Hard Rulesで規定）。
  * ベース動画に字幕を焼き付けた「後」にオーバーレイを合成すること。字幕が隠れてしまうため、字幕はフィルターチェーンの「最後」に適用する。
  * 毎回動画ソースを再文字起こしすること。キャッシュされたJSONを利用し、ソースが変更されない限り再実行は避ける。

## **18. 総評**

* **総合的な評価**:
  video-useは、「動画編集をLLMに任せる」というコンセプトを、トランスクリプトベースの解析とローカルスクリプトの組み合わせで極めて実用的なレベルに引き上げた画期的なオープンソースツールです。GUIを持たずAIエージェントに指示を出すというスタイルは、開発者にとって非常に強力で効率的なアプローチです。
* **推奨されるチームやプロジェクト**:
  日常的にチュートリアル動画やSNS向けのショート動画を作成する開発チームや、AIを活用した動画生成のパイプラインを構築したいエンジニアに強く推奨します。
* **選択時のポイント**:
  非技術者のクリエイターであればDescriptなどのGUIツールが適していますが、ターミナル作業に抵抗がなく、フルオートメーションで動画生成のワークフローを組みたい場合や、ローカルで細かく挙動を制御したい場合には、video-useが圧倒的な威力を発揮します。
