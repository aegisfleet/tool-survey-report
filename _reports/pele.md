# **Pele 調査レポート**

## **1. 基本情報**

* **ツール名**: Pele
* **ツールの読み方**: ペレ
* **開発元**: Obsidian
* **公式サイト**: [https://pele.run/](https://pele.run/)
* **関連リンク**:
  * GitHub: [https://github.com/obsidianmd/pele](https://github.com/obsidianmd/pele)
  * ドキュメント: [https://pele.run/api](https://pele.run/api)
* **カテゴリ**: ドキュメント生成/管理
* **概要**: PeleはMermaidダイアグラムをSVGにレンダリングするための軽量なオープンソースライブラリです。Mermaid.jsよりも大幅に高速で依存関係がありません。

## **2. 目的と主な利用シーン**

* **解決する課題**: 既存のMermaid.jsは機能が豊富ですが、バンドルサイズが大きく、レンダリングに時間がかかるという課題がありました。Peleはこれを軽量化・高速化します。
* **想定利用者**: Web開発者、Markdownパーサーの開発者、ドキュメント生成ツールの開発者
* **利用シーン**:
  * Webアプリケーション内でのMermaidダイアグラムの動的生成
  * Markdownエディタ（Obsidianなど）でのリアルタイムプレビュー
  * 静的サイトジェネレーターでのビルド時のSVG生成

## **3. 主要機能**

* **Mermaid構文のサポート**: Mermaid 12.1.0に組み込まれているすべてのダイアグラムタイプ（flowchart、sequence、classなど）をサポート。
* **超高速レンダリング**: 0.05～0.3ミリ秒での高速なレンダリングを実現。
* **軽量なバンドルサイズ**: gzip圧縮時で約230kBと、Mermaid.js（1.6MB）に比べて6倍軽量。
* **ゼロ依存**: 外部の依存ライブラリなしで動作。
* **CSS変数によるテーマ設定**: CSS変数を変更するだけで、再レンダリングなしに色やフォントを動的に変更可能。
* **セキュリティ機能**: ダイアグラムテキストのエスケープ、リンクやスタイルのフィルタリング、ソースと出力サイズの制限など。
* **数式のサポート**: `$$...$$` ラベルのレンダリングオプションを提供（HTML/MathML等を返すリゾルバをホスト側で用意）。

## **4. 動作原理・システム構成**

* **アーキテクチャ**: クライアント・サーバー両対応のライブラリ（ブラウザおよびNode.js環境）
* **主要コンポーネントとデータフロー**:
  * 入力としてMermaid構文のテキストを受け取り、独自のパーサーでAST（抽象構文木）を構築します。
  * ASTからSVG要素を生成し、文字列として出力します。
  * ブラウザ環境では `mount()` を使用してDOM要素に直接レンダリングし、コンテナの幅にレイアウトを適応させます。
* **特筆すべき要素技術**:
  * 差分ファジング（Differential Fuzzing）によるMermaid仕様との互換性テスト。
  * レンダリングプロセスは同期的であり、ランタイムのオーバーヘッドを最小限に抑えています。

## **5. 開始手順・セットアップ**

* **前提条件**:
  * Node.js環境またはモダンブラウザ
* **インストール/導入**:

  ```bash
  npm install pele
  ```
  または、pnpm, yarn, bunでインストール可能。CDN経由での利用も可能です。

* **初期設定**:
  * 特別な初期設定は不要です。

* **クイックスタート**:
  ```javascript
  import { render } from 'pele';

  const { svg } = render(`flowchart LR
    A[Mermaid text] --> B[SVG]`);

  document.querySelector('#diagram').innerHTML = svg;
  ```

## **6. 特徴・強み (Pros)**

* 圧倒的なパフォーマンス（Mermaid.js比で最大500倍高速）
* バンドルサイズの小ささ（Mermaid.jsの約1/6）
* 依存関係がゼロであるため、セキュリティリスクや競合が少ない
* CSS変数による柔軟かつ高速なテーマ切り替え
* ブラウザとNode.jsの両方で動作する汎用性

## **7. 弱み・注意点 (Cons)**

* Mermaid.js独自の機能拡張やプラグインには非対応の可能性がある
* レイアウトエンジンが独自のため、複雑な図の場合、Mermaid.jsと視覚的な結果が完全に一致しない場合がある
* 数式描画機能自体は内包しておらず、ホスト側でのリゾルバ実装が必要

## **12. セキュリティとコンプライアンス**

* **認証**: なし（ライブラリのため）
* **データ管理**: データはすべてローカル（クライアントまたは組み込みサーバー）で処理され、外部へのデータ送信はありません。
* **準拠規格**: 特になし（オープンソースライブラリとしてMITライセンスに準拠）。XSS対策としてダイアグラムテキストのエスケープ等の処理が含まれています。

## **13. 操作性 (UI/UX) と学習コスト**

* **UI/UX**: 開発者向けのライブラリであるため、APIの設計がシンプルで直感的です。
* **学習コスト**: 既存のMermaidユーザーであれば、記法はそのまま使えるため、導入の学習コストは非常に低いです。APIもシンプルです。

## **14. ベストプラクティス**

* **効果的な活用法 (Modern Practices)**:
  * アプリケーションのバンドルサイズを抑えるため、必要なダイアグラムタイプのみをオンデマンドでロードする（`import { renderAsync } from 'pele/lazy';`）。
  * テーマ切り替えはCSS変数の操作で行い、無駄な再レンダリングを避ける。
* **陥りやすい罠 (Antipatterns)**:
  * 古いMermaidの特殊な独自記法に依存した図をそのまま流用し、レイアウトが崩れることに気づかないこと。

## **18. 総評**

* **総合的な評価**:
  Peleは、Mermaid.jsが抱えていたパフォーマンスとバンドルサイズの課題を見事に解決した、非常に優秀なライブラリです。Webフロントエンド開発において、依存関係を減らしつつリッチな図解機能を提供できる点は大きな魅力です。
* **推奨されるチームやプロジェクト**:
  Webアプリケーション、ドキュメントツール、静的サイトジェネレーターを開発しているチーム。特にパフォーマンスを重視するプロジェクトに最適です。
* **選択時のポイント**:
  Mermaid.jsの完全な代替として機能しますが、レイアウトエンジンが異なるため、移行時は既存の図が意図通りに描画されるかどうかのテストを行うことが推奨されます。
