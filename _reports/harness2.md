# **Harness2 調査レポート**

## **1. 基本情報**

* **ツール名**: Harness2
* **ツールの読み方**: ハーネスツー
* **開発元**: Google Research
* **公式サイト**: [https://harness2.github.io/](https://harness2.github.io/)
* **関連リンク**:
  * GitHub: [https://github.com/google-research/harness2](https://github.com/google-research/harness2)
  * ドキュメント: [https://github.com/google-research/harness2/tree/main/docs](https://github.com/google-research/harness2/tree/main/docs)
* **カテゴリ**: 自律型AIエージェント
* **概要**: Harness2は、オープンワールドにおいて未知のタスクにエージェントが適応できるよう、エージェントを取り巻くシステム（Harness）を再帰的に最適化するプラグアンドプレイのフレームワークです。モデルの重みは固定したまま、システムプロンプトやツール、メモリなどを継続的に改善します。

## **2. 目的と主な利用シーン**

* **解決する課題**: 未知のタスクや領域に対して、モデルの再学習なしにエージェントのパフォーマンスや適応能力を向上させること。
* **想定利用者**: 自律型AIエージェントの開発者、AI研究者
* **利用シーン**:
  * 新しいドメインでのエージェントの振る舞いやシステムの評価と改善
  * JobBench、LAB、WorkBuddy-Benchといった各種ベンチマーク上でのエージェントの評価
  * 実行時のフィードバックに基づくプロンプトやツールインターフェースの動的最適化

## **3. 主要機能**

* **タスクレベルの再帰的最適化 (Task-level recursion)**: 「Propose（提案）– Probe（検証）– Compose（構成）」のステップを通じて、現在のタスクの実行Harnessを改善します。
* **Harnessingレベルの再帰的最適化 (Harnessing-level recursion)**: 各タスクから得られた教訓や採用されたHarnessを永続的な「改善Harness」に更新し、将来の最適化をガイドします。
* **8つの編集可能コンポーネント**: システムプロンプト、ガードレール、メモリ、ツールガイダンス、サブエージェント、スキル、スクリプト、プラグインなど、エージェント周辺のコンポーネントを編集できます。
* **複数の実行環境サポート**: OpenCodeとCodex executorをサポートし、安全な実行環境を提供します。
* **ベンチマーク対応**: JobBench（専門業務）、LAB（法務）、WorkBuddy-Bench（オフィス、Web、コード）に対応しています。
* **並列およびシーケンシャル再帰**: 複数の候補を並行して探索する「並列再帰」と、より深く最適化を続ける「シーケンシャル再帰」の両方をサポートします。

## **4. 動作原理・システム構成**

* **アーキテクチャ**: ローカルで実行可能なPythonベースのエージェント評価・最適化フレームワーク。モデル（GLM-5やGemini 3.5 Flashなど）へのAPI呼び出しを通じて機能します。
* **主要コンポーネントとデータフロー**:
  * エージェントExecutorが初期Harnessを使用してタスクを実行します。
  * Harness Editorが不変またはドメイン固有の編集を提案（Propose）します。
  * Candidate Probeがそれらを実行・検証（Probe）します。
  * Harness Composerが検証結果から最良のHarnessを構成（Compose）します。
  * Experience Reflectorがステップを振り返り、次のタスクのための改善Harnessを更新します。
* **特筆すべき要素技術**:
  * コントラスティブな「Propose–Probe–Compose」アプローチによる、正解（Ground-truth）フィードバックなしでの自己改善。
  * モデルの重み（Weights）を一切変更せず、周辺環境（システムプロンプト、ツール、メモリ等）のみを最適化。

## **5. 開始手順・セットアップ**

* **前提条件**:
  * Linux環境
  * Python 3.12
  * uv パッケージマネージャー
  * Node.js 20+（モデルバックドベンチマーク用）
  * 各種ベンチマークに必要な依存ツール（Docker, Pandoc, Popplerなど）
* **インストール/導入**:

  ```bash
  uv venv --python 3.12 .venv
  source .venv/bin/activate
  uv pip install -e '.[render]'
  ```

* **初期設定**:
  * APIキー等の設定（`.env.example` をコピーして `.env` を作成）
  * `gcloud auth application-default login` （Google Cloudを利用する場合）
* **クイックスタート**:
  * デモの実行（モデルAPI不要）:
    ```bash
    harness2-demo --output runs/demo --k 2
    ```
  * JobBenchのセットアップと実行例:
    ```bash
    harness2-setup jb
    harness2 --bench jb --k 1 --mode parallel
    ```

## **6. 特徴・強み (Pros)**

* モデルのファインチューニングや重み更新が不要なため、API経由で利用可能なプロプライエタリモデルでもパフォーマンス向上を図れる。
* 未知のタスクに対しても、実行時のフィードバックのみ（正解データ不要）でエージェント自身を継続的に最適化できる。
* タスクごとの最適化だけでなく、タスク間での永続的な知識蓄積（Harnessing-level recursion）を行う点が画期的。

## **7. 弱み・注意点 (Cons)**

* 実装やセットアップにPythonや各種周辺ツールの知識が必要であり、一般ユーザーにはハードルが高い。
* 各タスクごとの再帰的な探索と検証（Propose-Probe-Compose）に複数回のモデル呼び出しが発生するため、APIコストと実行時間が増大する。
* ベンチマーク環境ごとに依存ツール（DockerやPandocなど）の事前インストールが必要。

## **14. ベストプラクティス**

* **効果的な活用法 (Modern Practices)**:
  * 評価時にAPIコストを抑えるため、最初は `--max-tasks` を設定して少数タスクで動作確認を行う。
  * `harness2-demo` を用いて、モデルAPIなしでの再帰的最適化プロセスの挙動を理解する。
* **陥りやすい罠 (Antipatterns)**:
  * ネットワーク制限を行わずにベンチマークを実行すると、モデルがWeb上の正解データにアクセスしてしまい、公平な評価ができなくなる（データコンタミネーション）。

## **18. 総評**

* **総合的な評価**:
  Harness2は、モデルの重みを変更せずに、エージェント周辺のシステムコンポーネントを動的かつ再帰的に最適化するという新しいアプローチを提供する研究用フレームワークです。API呼び出しのコストやセットアップの複雑さはあるものの、未知のタスクに対する適応能力を大幅に引き上げる可能性を秘めています。
* **推奨されるチームやプロジェクト**:
  最先端のAIエージェントアーキテクチャの研究開発を行うチームや、LLMのポテンシャルを最大限に引き出すためのシステムプロンプトやツール連携の最適化に取り組むプロジェクトに推奨されます。
* **選択時のポイント**:
  すぐに業務に導入できる完成されたSaaSではなく、研究評価用・開発者向けのツールセットであることを理解した上で、高度な自律型エージェントの設計やベンチマーク評価を行いたい場合に選択すべきフレームワークです。
