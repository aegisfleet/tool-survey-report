# **DeepSeek Harness 調査レポート**

## **1. 基本情報**

* **ツール名**: DeepSeek Harness
* **ツールの読み方**: ディープシーク・ハーネス
* **開発元**: DeepSeek-AI
* **公式サイト**: [https://www.deepseek.com/en/harness/](https://www.deepseek.com/en/harness/)
* **関連リンク**:
  * GitHub: [https://github.com/deepseek-ai/deepseek-harness](https://github.com/deepseek-ai/deepseek-harness)
  * ドキュメント: [https://deepseek-harness.github.io/deepseek-harness/](https://deepseek-harness.github.io/deepseek-harness/)
* **カテゴリ**: エージェントエコシステム/基盤
* **概要**: 「すべてがプラグイン（everything-is-a-plugin）」という思想のもと、Cordisを基盤として開発されたオープンソースのエージェントハーネスです。デスクトップアプリやWeb UIとして動作し、コーディング、データ分析、日常タスクの自動化などを実現します。

## **2. 目的と主な利用シーン**

* **解決する課題**: 単一のタスクだけでなく、複雑で動的なコンポーネントの構成や拡張が必要な自律型エージェントの開発と実行を、統一された基盤上で容易にすること。
* **想定利用者**: AIエージェントを自作したい開発者、リサーチャー、タスク自動化を行いたい一般ユーザー。
* **利用シーン**:
  * **日常業務**: ファイルの整理、データ分析、ドキュメントやスライドの作成。
  * **コーディング支援**: リポジトリの探索、バグ修正、機能開発、テスト実行。
  * **バックグラウンド処理**: スクリプトの実行、ファイルのバッチ処理、進行状況のトラッキングやスケジュール実行（定期タスク）。

## **3. 主要機能**

* **プラグインシステム（Everything is a plugin）**: 全てのツール、スキル、インターフェースがプラグインとして構成され、動的に追加や自作（クリエイターモード）が可能。
* **デスクトップ＆Web UI**: ローカルのデスクトップアプリとして、あるいはnpmコマンドから簡単に起動できるWeb UIとして利用可能。
* **マルチタスク対応**: Word、Excel、HTML、TypeScript、PDF等の多様なファイルを読み書きし、結果を直接プレビューできる。
* **スケジュール機能**: 「Scheduled tasks」プラグインにより、定期的なタスクの自動実行が可能。
* **開発者ツール・実行トレース**: ツールコールの詳細、実行時間、ペイロードなどの詳細なランタイム情報をタイムライン形式で確認・トラブルシューティングできる。
* **GitHub連携**: Agent teamsやAuto approval reviewなどのプラグインを用いたチームコラボレーション。
* **Model Context Protocol (MCP)**: Memory MCPなどの連携により、外部ツールやプロバイダーとシームレスに連携可能。

## **4. 動作原理・システム構成**

* **アーキテクチャ**: ローカルファーストのクライアント・サーバー構成（Electron/デスクトップ環境、またはWebサーバー）。
* **主要コンポーネントとデータフロー**:
  * 基盤技術として **[Cordis](https://github.com/cordiverse/cordis)** を採用し、空間的・時間的な合成（Spatiotemporal Composability）を実現。
  * コンポーネント（プラグイン）は、追加時にリアクティブに依存関係を解決し（空間的合成）、削除時には副作用を完全に巻き戻す（時間的合成）仕組みを持つ。
  * ユーザーはチャットインターフェースを通じてエージェントと対話し、エージェントはCordisが管理するコンテキストを通じてツールを実行する。
* **特筆すべき要素技術**:
  * 論文「A Programming Paradigm for Spatiotemporal Composability」で示された、コンテキスト駆動型のエフェクトトラッキングおよびホットモジュールリプレイスメント機能。

## **5. 開始手順・セットアップ**

* **前提条件**:
  * Node.js環境（npm実行のため）
  * アカウント作成は不要（ローカル実行）
* **インストール/導入**:

  npmからの起動（Web UI）の場合:
  ```bash
  npx @deepseek-ai/dsh web
  ```
  ※デフォルトで `http://127.0.0.1:3080` で起動します。

  ソースからのビルドの場合:
  ```bash
  git clone https://github.com/deepseek-ai/deepseek-harness.git
  cd deepseek-harness
  pnpm install
  pnpm run build
  pnpm dsh web
  ```

* **初期設定**:
  * Web UIの「Settings → Models」からDeepSeek APIキーを設定し保存することで、再起動なしですぐにモデルを利用可能。
* **クイックスタート**:
  * Web UIでワークスペースディレクトリを選択し、「Summarize this repository and identify its main packages.」などのプロンプトを送信する。

## **6. 特徴・強み (Pros)**

* 「すべてがプラグイン」による極めて高い拡張性とカスタマイズ性。
* 論文に基づく堅牢な基盤（Cordis）により、プラグインの動的な追加・削除が安全に行える。
* 実行トレース画面がリッチで、開発者がエージェントの思考やツールコールの履歴を詳細に追跡・デバッグしやすい。
* 会話形式（クリエイターモード）で指示するだけで、エージェント自身が新しいプラグイン（例: ポモドーロタイマーなど）を開発し、システムに組み込むことができる。

## **7. 弱み・注意点 (Cons)**

* 2026年10月現在、開発者プレビュー段階であり、今後互換性を損なう破壊的変更（Breaking Changes）が予告されている。
* フル機能を利用するためには基盤となるCordisアーキテクチャの理解が必要となり、学習コストがやや高い。
* 日本語UIの完全対応や国内サポート体制は発展途上（ドキュメントやUIの一部は日本語対応されている）。

* **認証**: ローカル起動時はローカルのAPIキー設定にて管理。

* **準拠規格**: オープンソースプロジェクトのため、特定のコンプライアンス認証は公式サイトでは公開されていない。セキュリティについてはリポジトリの `SAFETY.md` を参照のこと。

## **13. 操作性 (UI/UX) と学習コスト**

* **UI/UX**: モダンで直感的なWeb UIおよびデスクトップアプリ。タイムライン形式での実行トレース、ファイル別のプレビュー画面など、開発者目線のDXが良好。
* **学習コスト**: クライアントとしての利用は容易だが、Cordisによる独自のプラグイン開発（コンテキストやコエフェクトの概念）をマスターするには一定の学習が必要。

## **14. ベストプラクティス**

* **効果的な活用法 (Modern Practices)**:
  * クリエイターモードを活用し、足りない機能や独自のワークフローを自然言語でプラグイン化して組み込む。
  * 定期的なリポジトリの要約やテスト実行を「Scheduled tasks」として登録し、自動化する。
* **陥りやすい罠 (Antipatterns)**:
  * 本番環境で未検証のスクリプトを自動承認設定で走らせること（副作用の巻き戻しができるとはいえ、外部APIへの影響は元に戻せない）。
  * 破壊的変更があるプレビュー版であることを考慮せず、重要なシステムに強固に組み込みすぎること。

## **18. 総評**

* **総合的な評価**:
  DeepSeek Harnessは、Cordisアーキテクチャによる時間的・空間的なコンポーネント合成を活かした、次世代のオープンソースAIエージェント基盤です。単なるCLIツールではなく、デスクトップアプリやWeb UIを備え、実行トレースもリッチであるため、開発者体験が非常に優れています。
* **推奨されるチームやプロジェクト**:
  日常タスクの自動化から高度なコーディング支援まで、AIエージェントの挙動を自分のワークフローに合わせて細かくカスタマイズしたい開発者や研究チームに強く推奨されます。
* **選択時のポイント**:
  OpenHandsなど既存のOSSエージェントツールと比較した場合、「すべてがプラグインである」という思想と、それに伴う拡張性（クリエイターモードによる動的生成など）に価値を感じるかどうかが選択の分かれ目となります。
