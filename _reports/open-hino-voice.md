# **OpenHinoVoice 調査レポート**

## **1. 基本情報**

* **ツール名**: OpenHinoVoice
* **ツールの読み方**: オープンヒノボイス
* **開発元**: iiinno (個人開発、GitHub: [@iiinno](https://github.com/iiinno))
* **公式サイト**: [https://github.com/iiinno/OpenHinoVoice](https://github.com/iiinno/OpenHinoVoice)
* **関連リンク**:
  * GitHub: [https://github.com/iiinno/OpenHinoVoice](https://github.com/iiinno/OpenHinoVoice)
* **カテゴリ**: デスクトップ/環境操作
* **概要**: OpenHinoVoiceは、Windows環境で動作するオープンソースの日本語音声入力常駐アプリケーションです。音声認識処理をPCローカル内で完結させることで音声データを外部クラウドへ送信せずプライバシーを保護しつつ、認識後のテキストに対してChatGPT、OpenCode Go、OpenAI互換APIなどを用いた言い淀み除去・句読点整形を行えます。整形完了後はアクティブなウィンドウの入力欄へ直接貼り付けを行い、クリップボードの内容退避やEnter非送信など誤操作防止に配慮した設計が特徴です。

## **2. 目的と主な利用シーン**

* **解決する課題**:
  * クラウド型音声入力ツールにおける社内機密情報や個人情報の漏洩リスク
  * 音声認識特有の言い淀み（「えーと」「あのー」など）や不自然な改行の手動修正の手間
  * 音声入力結果を貼り付ける際にクリップボード既存データが消去されたり、Enterキーが自動送信されてチャットツール等で誤爆するリスク
  * 有料音声入力SaaSの継続的なサブスクリプションコスト負担
* **想定利用者**:
  * 機密情報を扱うため外部音声送信が禁止されている企業のエンジニア・ビジネスパーソン
  * ドキュメント作成、ブログ執筆、チャットコミュニケーションを音声で高速化したいWindowsユーザー
  * 既存のChatGPT Plus/Pro契約やOpenAI APIキーを活用して低コストで高品質な音声入力を実現したい人
* **利用シーン**:
  * **コードコメント・コミットメッセージの起草**: IDEで作業中にホットキーを押して要件を話し、整えられた自然な日本語を即座に入力欄へ挿入
  * **Slack / Teamsでの長文返信**: 誤送信（Enter誤爆）の心配なく、話し言葉を自然なビジネス文体に自動整形して貼り付け
  * **議事録・ドキュメントの下書き作成**: マイクからの音声入力や保存済みWAVファイルのローカル文字起こしを実行し、AIによる自動校正を適用

## **3. 主要機能**

* **ローカル完結の高速日本語音声認識**: `speech.cpp` と日本語音声認識モデル `Haas-ja-v1.0`（約0.35GB）を組み合わせ、音声データを端末外に出すことなく高速かつ高精度に文字起こしを実行。
* **柔軟なAI文章整形バックエンド**: ChatGPT Plus/ProアカウントによるOAuth連携（追加料金不要）、OpenCode Go、OpenAI API（`gpt-6-luna`等）、カスタムOpenAI互換エンドポイントから選択可能。
* **二重Enterによる即時貼り付けスキップ**: Enterを1回押すとAI整形を待って貼り付け、待たずにもう1回Enterを押すと整形前の生テキストを即時貼り付け可能。
* **クリップボード一時退避・復元**: OLEクリップボードAPIを用い、既存のクリップボードデータ（テキスト、画像、ファイル等）を保持したまま貼り付けを実行し、直後に復元。
* **誤爆防止のEnter非送信設計**: テキスト貼り付け後にEnterキー（改行送信）を送出しないため、Slackなどのチャットで意図せず送信されてしまう事故を防止。
* **日の丸型ミニマルUIインジケーター**: 録音中は画面上部に日本の国旗を模した丸型インジケーターが表示され、音声入力レベルに応じてバーがリアルタイムに伸縮。
* **用語辞書・確定置換機能**: 固有名詞や専門用語の辞書を登録可能。「正式表記」はAI整形や認識のヒント情報として機能し、「確定置換する別表記」はAIなしでも確実に文字列置換。
* **入力先アプリケーション文脈の考慮**: アクティブウィンドウのプロセス名（実行ファイル名）を検出し、プロンプトのコンテキストとしてAIに伝達（画面キャプチャや周辺テキストの読み取りは行わない）。
* **DPAPI暗号化による短期復旧履歴**: 認識テキストを貼り付け前にWindows DPAPIで暗号化して短期保存（最大200件、16MiB）。貼り付けに失敗した場合でもタスクトレイから再コピーや別ウィンドウへの再貼り付け（3秒猶予）が可能。
* **ローカルWAVファイル文字起こし**: マイクからの直接入力だけでなく、128MiB・10分以内のWAVファイル（PCM16または32ビット浮動小数点）をローカルで文字起こし可能。

## **4. 動作原理・システム構成**

* **アーキテクチャ**: ローカルファーストのハイブリッド構成。音声認識および入力制御はWindowsネイティブで完全ローカル動作し、文章整形処理のみユーザー設定に応じて外部LLM APIを呼び出す。

```mermaid
flowchart TD
  subgraph WindowsOS["Windows デスクトップ環境"]
    User[ユーザー発話] -->|マイク入力| Audio["audio.rs\n(cpal / WASAPI)"]
    Hook["hook.rs\n(WH_KEYBOARD_LL)"] -->|F8 / Enter / Esc 検知| State["state.rs\n(状態機械)"]
    State -->|録音レベル反映| Overlay["overlay.rs\n(DirectWrite / GDI レイヤードUI)"]
    Paste["paste.rs\n(OLE Clipboard & SendInput)"] -->|Ctrl+V 貼付| TargetApp["入力先アクティブウィンドウ"]
  end

  subgraph LocalASR["ローカル推論層 (speech.cpp)"]
    Audio -->|PCMチャンク (パイプ通信)| SpeechExe["speech.exe\n(CREATE_NO_WINDOW)"]
    SpeechExe -->|推論実行| Model["Haas-ja-v1.0 (GGUF)\nローカルモデル約0.35GB"]
    SpeechExe -->|認識生テキスト| ASR["asr.rs"]
  end

  subgraph Processing["テキスト処理・整形層"]
    ASR --> Lexicon["lexicon.rs\n(用語辞書・確定置換)"]
    Lexicon --> History["history.rs\n(DPAPI暗号化短期履歴)"]
    Lexicon --> AppDetect["app_detect.rs\n(入力先プロセス名取得)"]
    AppDetect --> Format["format.rs\n(AI文章整形エンジン)"]
  end

  subgraph ExternalLLM["外部LLMサービス (任意)"]
    Format -->|HTTPS POST| ChatGPT["ChatGPT (OAuth / DPAPI Token)"]
    Format -->|HTTPS POST| OpenCode["OpenCode Go (deepseek等)"]
    Format -->|HTTPS POST| OpenAI["OpenAI API / 互換エンドポイント"]
  end

  Format -->|整形テキスト| Paste
  ASR -.->|2回目Enter時 / 生テキスト| Paste
```

* **主要コンポーネントとデータフロー**:
  * **音声キャプチャと認識**: `cpal` クレートを介してマイク音声を取得し、標準入出力パイプを通じて別プロセスの `speech.exe` に送出。`Haas-ja-v1.0` GGUFモデルによってローカルで推論され、認識文字列が生成されます。
  * **入力先検知と辞書前処理**: `GetForegroundWindow` 等により入力対象のプロセス名を取得。登録された用語辞書に基づき、確定置換対象の単語を置換しつつ、正式表記情報をプロンプトへ注入します。
  * **AI整形とプロンプトキャッシュ**: `ureq` を用いてHTTPS通信を行い、プロセスの生存期間中は同一の `session_id` を維持することでLLM側のプロンプトキャッシュ効率を最大化。HTTP 429や一時的ネットワークエラー時は指数バックオフで最大3回再試行します。
  * **安全な貼り付けメカニズム**: `OleGetClipboard` で現在のクリップボード状態オブジェクトを保持し、認識結果をクリップボードに設定して `SendInput` で Ctrl+V を発行。完了後に `OleSetClipboard` で以前のクリップボード内容を完全復元します。
* **特筆すべき要素技術**:
  * **低レベルフック (`WH_KEYBOARD_LL`)**: バックグラウンド常駐中もグローバルなキーボード入力を遅延なく捕捉。
  * **Windows DPAPI暗号化**: 復旧用短期履歴およびChatGPTサインイン時の認証トークンを端末・ユーザー固有のDPAPIで暗号化して保存。
  * **非同期Bounded Writer**: `speech.exe` へのパイプ書き込みを別スレッドの有界キューに分離し、エンジン側の読み込み遅延やフリーズ時にもUIメインループが巻き込まれてハングアップしないよう堅牢化。

## **5. 開始手順・セットアップ**

* **前提条件**:
  * Windows 10 または Windows 11 (x64)
  * PC用マイク（内蔵または外付け）
  * 管理者権限は不要（一般ユーザー権限で導入・動作可能）
* **インストール/導入**:

  1. **音声認識エンジン（speech.cpp）の導入**:
     PowerShellを開き、公式インストーラーを実行します。

     ```powershell
     irm https://raw.githubusercontent.com/nyosegawa/speech.cpp/main/install.ps1 | iex
     ```

  2. **OpenHinoVoiceの配置と起動**:
     GitHub Releasesから最新の `openhinovoice.exe` をダウンロードし、任意のフォルダ（例: `%LOCALAPPDATA%\Programs\OpenHinoVoice`）に配置して実行します。

     ```powershell
     $dir = "$env:LOCALAPPDATA\Programs\OpenHinoVoice"
     New-Item -ItemType Directory -Force $dir | Out-Null
     Invoke-WebRequest https://github.com/iiinno/OpenHinoVoice/releases/latest/download/openhinovoice.exe -OutFile "$dir\openhinovoice.exe"
     Start-Process "$dir\openhinovoice.exe"
     ```

* **初期設定**:
  1. タスクトレイのアイコンを右クリックし、「設定」を開きます。
  2. 「一般」タブで録音開始キー（初期値: F8）を確認・変更し、必要に応じて「Windows にサインインしたときに起動する」を有効化します。
  3. 「整形(AI)」タブで接続先を選択します（ChatGPT Plus/Pro契約者は「ChatGPT のプラン」を選びブラウザ経由でサインイン、またはOpenAI APIキーを入力）。
  4. 「接続テスト」をクリックして正常に整形されることを確認し、「保存」を押します。
* **クイックスタート**:
  1. メモ帳などのテキストエディタを開き、カーソルを入力欄に合わせます。
  2. 録音開始キー（F8）を押し、マイクに向かって話します（初回のみ約0.35GBのモデルが自動ダウンロードされます）。
  3. 話し終えたら Enter キーを押します。数秒で整えられたテキストが自動入力されます。

## **6. 特徴・強み (Pros)**

* **圧倒的なプライバシーと機密保護**: 音声認識処理がPC内で完全完結するため、社内会話や機密情報を含む音声がネットワーク上に流出する懸念が一切ありません。
* **日常業務に最適化された安全な貼り付け設計**: クリップボード内容の自動退避・復元、およびEnterキーを送信しない設計により、クリップボード汚染やチャットでの誤送信リスクを排除しています。
* **ChatGPT契約枠を活用した追加費用ゼロ運用**: ChatGPT PlusやProの契約者がブラウザサインインすることで、従量課金APIキーを用意することなくAI文章整形を利用可能です。
* **二重Enterによるレイテンシゼロの生入力**: AI整形の完了を待たずにもう一度Enterを押すだけで、ローカルASRの生テキストが即座に貼り付けられる直感的なバイパス導線が用意されています。
* **用語辞書と復旧履歴による高い信頼性**: 専門用語・固有名詞の誤変換を防ぐ辞書機能に加え、万一の貼り付け失敗時にもDPAPI暗号化短期履歴からワンクリックでリカバリ可能です。

## **7. 弱み・注意点 (Cons)**

* **Windows専用プラットフォーム**: WindowsネイティブAPI（Win32, WASAPI, DPAPI等）に深く依存しているため、macOSやLinuxでは動作しません。
* **未署名バイナリによる初期起動時の警告**: 配布されているexeファイルはコード署名証明書が付与されていないため、初回起動時にWindows SmartScreenの警告画面（「WindowsによってPCが保護されました」）が表示され、手動で「実行」を選択する必要があります。
* **外部ASRエンジン（speech.cpp）の事前導入が前提**: 単一のexe単体では完結せず、初回にPowerShellスクリプトによる `speech.cpp` のセットアップが必要です。
* **画面全体の深いコンテキスト認識には非対応**: Aqua Voiceなどのように画面上のエディタコード全体を深く解析して文脈を推論する機能はなく、入力先プロセス名の伝達に留まります。

## **11. エコシステムと連携**

### **11.1 API・外部サービス連携**

* **API**: 本アプリ自体が外部向けWeb APIを提供するサーバー機能はありませんが、標準的なOpenAI Chat Completions API仕様に準拠したエンドポイントであれば任意の後続LLMと連携可能です。
* **外部サービス連携**:
  * **OpenAI (ChatGPT OAuth / API)**: ChatGPT Plus/ProのPKCEサインイン連携およびOpenAI公式APIキー接続に対応。
  * **OpenCode Go**: コーディングエージェント向けプラットフォームのAPI接続に対応。
  * **speech.cpp**: nyosegawa氏が開発するC++音声認識バックエンドと標準入出力パイプでシームレスに連携。

### **11.2 技術スタックとの相性**

| 技術スタック | 相性 | メリット・推奨理由 | 懸念点・注意点 |
|:---|:---:|:---|:---|
| **Windows 11 / 10** | ◎ | Win32 API、WASAPI、DPAPIをフル活用したネイティブ統合 | OS標準の仕様に準拠 |
| **テキストエディタ (VS Code, メモ帳等)** | ◎ | クリップボード復元とCtrl+Vによりあらゆるエディタに入力可能 | フォーカスを合わせた状態で貼り付けが必要 |
| **チャットツール (Slack, Teams, Discord)** | ◎ | Enterキーを送出しない設計のため意図しない即時送信が発生しない | 特になし |
| **Logi Options+ 等のマウス設定** | ◯ | マウスボタンにCtrl+Alt+J等を割り当てることでワンボタン録音が可能 | ショートカットの重複に留意 |
| **macOS / Linux** | × | Windows固有のWin32/OLE APIに依存しているため動作不可 | プラットフォーム非対応 |

## **12. セキュリティとコンプライアンス**

* **認証**: ChatGPTプランとの連携には、OpenAIがOSS向けに推奨するOAuth PKCE方式（Sign in with ChatGPT）を採用。APIキーの直書きやチャット経由の共有を排除しています。
* **データ管理**:
  * 音声認識処理はすべて端末ローカルのメモリおよびCPU/GPUで実行され、音声データが外部サーバーへ送信されることはありません。
  * 外部AIサービスへ送信されるのは「音声認識後のテキスト」のみです。
  * 復旧用短期履歴およびChatGPTセッショントークンは、Windowsユーザーアカウントに紐づくDPAPI（Data Protection API）で暗号化してローカル保存されます。
  * AI整形の改善用履歴（`format-history.jsonl`）は完全opt-in（初期設定オフ）であり、ローカル端末内でのみ管理されます。
* **準拠規格**: 個人開発OSSのためSOC2やISO認証の第三者認証は取得していませんが、ソースコードはMITライセンスで完全公開されており、セキュリティや実装の透明性が確保されています。

## **13. 操作性 (UI/UX) と学習コスト**

* **UI/UX**:
  * 直感的なホットキー操作（F8で録音、Enterで確定、Escでキャンセル）。
  * 録音中は画面上部にミニマルな「日の丸」インジケーターが表示され、音声レベルが視覚的に確認できるため録音漏れを防げます。
  * 設定画面は `egui` による軽量なGUIが提供されており、タブ構成で設定項目が分かりやすく整理されています。
* **学習コスト**: 極めて低く、導入後は通常のキーボードタイピングの延長として数分の試用で直感的に使いこなすことができます。

## **14. ベストプラクティス**

* **効果的な活用法 (Modern Practices)**:
  * **マウスボタンへのホットキー割り当て**: マウスユーティリティ（Logi Options+など）でサイドボタンにショートカットキー（例: Ctrl+Alt+J）を割り当てることで、キーボードから手を離さずにワンタッチで音声入力が可能になります。
  * **用語辞書の積極的な活用**: 誤認識しやすい社内用語、人名、最新の技術スタック（例: Next.js, vLLM等）を用語辞書の「正式表記」に登録しておくことで、ローカルASRの認識精度とAI整形の正確性を大幅に高められます。
  * **二重Enterの使い分け**: 箇条書きや走り書きのメモなど、言い淀み除去が不要で即座に入力したい場合はEnterを2回押して待ち時間なしで入力し、清書したい文章では1回押してAIに整形させる使い分けが効率的です。
* **陥りやすい罠 (Antipatterns)**:
  * **辞書の確定置換の乱用**: 「確定置換する別表記」は文脈を考慮せず機械的に文字列を置換するため、一般的な多義語に設定すると意図しない箇所まで置換されてしまいます。文脈依存の単語は「正式表記」のみを登録し、AIに判断させるのが安全です。
  * **貼り付け先アプリのフォーカス切り替えミス**: ホットキーを押した後に別のウィンドウをクリックしてしまうと、入力先が意図しないアプリに切り替わる恐れがあります。

## **18. 総評**

* **総合的な評価**: OpenHinoVoiceは、Windows環境において「音声データの完全ローカル処理」と「最新LLMによる高度な文章整形」という2つの長所を巧みに統合した優れたオープンソースユーティリティです。クリップボードデータの自動退避・復元やEnterキーの非送信、用語辞書、DPAPI暗号化による短期復旧履歴など、日常のPC作業でストレスや事故を生まないための細やかな配慮が随所に施されています。
* **推奨されるチームやプロジェクト**:
  * 社内ポリシーで外部クラウドへの音声送信が禁止されている開発チーム・企業
  * ChatGPT Plus/Proをすでに契約しており、追加費用をかけずに高精度な日本語音声入力を導入したいユーザー
  * Slackやドキュメント執筆で音声入力を多用し、タイピング疲労を軽減したいWindowsユーザー
* **選択時のポイント**:
  * 音声プライバシーと完全無料での運用、安全な貼り付け操作を最優先する場合は **OpenHinoVoice** が最適な選択肢となります。
  * macOSやスマートフォンでの利用、あるいはエディタ画面全体のコード文脈を把握した音声プログラミングを求める場合は、**Typeless** や **Aqua Voice** などの商用クラウドツールの併用を検討すると良いでしょう。
