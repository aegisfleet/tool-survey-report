# **Amazon Q Developer 調査レポート**

## **1. 基本情報**

* **ツール名**: Amazon Q Developer
* **ツールの読み方**: アマゾン キュー デベロッパー
* **開発元**: Amazon Web Services (AWS)
* **公式サイト**: [https://aws.amazon.com/q/developer/](https://aws.amazon.com/q/developer/)
* **関連リンク**:
  * ドキュメント: [https://docs.aws.amazon.com/amazonq/latest/qdeveloper-ug/what-is.html](https://docs.aws.amazon.com/amazonq/latest/qdeveloper-ug/what-is.html)
  * Kiro公式サイト: [https://kiro.dev/](https://kiro.dev/)
* **カテゴリ**: AIコーディング支援
* **概要**: Amazon Q Developerは、AWS上でのアプリケーション構築、デバッグ、運用、レガシーコード変換を支援する生成AIアシスタントです。2026年5月に新規アカウントおよび有償サブスクリプションの登録受付が停止され、2027年4月30日にIDEプラグインを含むすべてのサポート（End-of-Support）が終了することが発表されました。AWSはスペック駆動開発（SDD）を採用した次世代AIエージェント開発環境「Kiro」への完全移行を推奨しています。一方、AWS Management Console上のクラウド運用・監視支援レイヤーとしては、2026年10月に数百のAWS APIを横断してヘルスダッシュボードや時系列チャートをチャット画面に動的描画する高度なビジュアライゼーション機能が提供されるなど、クラウドインフラ管理のAIアシスタントとしての進化が続けられています。

## **2. 目的と主な利用シーン**

* **解決する課題**: 
  * 複雑なAWSアーキテクチャの設計・設定にかかる調査時間の短縮
  * 障害発生時における複数サービス間のメトリクス横断調査・原因特定の迅速化
  * Javaや.NETなどのレガシーアプリケーションのモダナイゼーション工数削減
  * 定型的なコーディングやテストコード作成作業の自動化
* **想定利用者**: 既存のAWSを利用するソフトウェアエンジニア、DevOpsエンジニア、SRE、インフラアーキテクト。
* **利用シーン**:
  * **AWSコンソールでの運用監視・障害調査**: 自然言語による問い合わせから、ステータスインジケーター付きヘルスダッシュボードや異常検知付き時系列チャートを即座に生成し、インフラの状態を可視化。
  * **IDE内でのコード生成・補完**: VS CodeやJetBrains等のIDE上で、コメントや関数の意図からAWS SDK/CDKやビジネスロジックのコードを自動生成。
  * **レガシーシステムのバージョンアップ**: Java 8/11からJava 17/21へのバージョンアップグレードやフレームワーク移行における依存関係の更新とコード変換。
  * **セキュリティ診断**: プロジェクト内の潜在的な脆弱性スキャンとワンクリック修正の適用。
  * **GitHubプルリクエスト内でのコード改善**: PR内で`/q`コマンドを用いてAIエージェントに直接修正指示やテスト生成を依頼。

## **3. 主要機能**

* **コンソール高度ビジュアライゼーション (Enhanced Console Visualizations)**: AWSマネジメントコンソール内で何百ものAWS APIを自律的に横断し、テキスト回答に加えて「ヘルスダッシュボード」「トレンド線・異常検知付き時系列チャート」「トラブルシューティング診断アーティファクト」を動的にチャットパネルへレンダリング。
* **コード生成とインライン補完**: IDE上で文脈を解釈し、単一行・複数行のコード補完や関数全体の実装を高速に提案。
* **Amazon Q Chat**: IDEやAWSコンソール上で対話形式による技術的な相談、エラーログの分析、AWSベストプラクティスに基づいた構成提案を提供。
* **Amazon Q Developer Agents**: 機能の実装、ドキュメント生成、単体テスト作成、コードレビューなどを自律的に反復実行するエージェント機能。
* **コード変換 (Code Transformation)**: Javaや.NETアプリケーションのバージョンアップグレードやWindowsからLinuxへの移植タスクを、隔離されたクラウドビルド環境で自動実行。
* **セキュリティスキャン & 自動修正**: OWASP Top 10やAWSベストプラクティスに基づきコードの脆弱性を検出、推奨パッチを提示。
* **GitHub統合ワークフロー**: GitHubプルリクエストのコメントで`/q`コマンドを介して対話しながら、AIが自動でブランチを切って修正コミットを作成。
* **Kiro CLI (旧 Amazon Q CLI統合先)**: 旧来のターミナルCLI機能は次世代エージェント「Kiro CLI」へと統合・刷新され、スペック駆動での自律コマンド実行を支援。

## **4. 動作原理・システム構成**

* **アーキテクチャ**: クラウド完結型SaaS ＋ IDE拡張 / AWSマネジメントコンソール統合モデル。クライアント層とAWSクラウド上のAmazon QバックエンドがセキュアなTLS通信で接続され、IAM Identity CenterやAWS Builder IDを通じてきめ細やかなアクセス制御が行われる。

* **主要コンポーネントとデータフロー**:
  * **コンテキスト収集とプロンプト構築**: IDE側ではアクティブなファイル、開いているタブ、カーソル周辺のコード、プロジェクト構造を解析。AWSコンソール側では現在のリージョン、リソースARN、閲覧中のコンソール画面情報をコンテキストとしてGatewayへ送信。
  * **APIオーケストレーションと可視化描画**: コンソールからの問い合わせ時、推論モデルがユーザーの意図を分解し、CloudWatchや各サービスAPI（何百種類）を並行呼び出し。収集したメトリクスを基にビジュアライゼーションエンジンがステータスインジケーターや時系列異常検知チャートなどのJSONアーティファクトを構築し、フロントエンドに直接描画。
  * **セキュアなコード変換パイプライン**: Code Transformation実行時は、ユーザーのコードリポジトリがAWS上のマネージド隔離コンテナに安全に転送され、抽象構文木（AST）解析、ビルド、依存関係の更新、テスト実行を経て検証済みの差分（Diff/Pull Request）を生成。
* **特筆すべき要素技術**:
  * **Amazon Bedrock基盤**: 最先端のLLM（ClaudeファミリやAWS独自チューニングモデル）をセキュアに連携。
  * **マルチAPI自律オーケストレーション**: 複数リージョン・複数サービスのテレメトリをリアルタイムに集約する分析技術。
  * **Model Context Protocol (MCP) との連動**: 次世代環境Kiroへの移行を見据え、ツール定義やリソース連携プロトコルの統一が推進されている。

## **5. 開始手順・セットアップ**

> [!WARNING]
> **新規登録停止に関する注意（2026年5月15日発効）**
> Amazon Q Developerは2026年5月15日をもって新規のアカウント登録および有償サブスクリプションの受付を停止しました。新規に開発環境を導入する場合は、AWS公式の後継ツールである「Kiro（[https://kiro.dev/](https://kiro.dev/)）」をご利用ください。以下は登録済みの既存アカウントでの利用手順です。

* **前提条件**:
  * 既存のAWSアカウントまたは登録済みAWS Builder ID
  * 対応IDE（VS Code, IntelliJ IDEA, PyCharm, Visual Studio等）
* **インストール/導入**:
  * VS CodeまたはJetBrainsの拡張機能マーケットプレイスで「Amazon Q」を検索してインストール。
  * ターミナル操作を希望する場合はKiro CLIインストーラー（`curl -fsSL https://kiro.dev/install.sh | bash`）を利用。
* **初期設定**:
  * IDEのサイドバーに表示されるAmazon Qアイコンをクリック。
  * 「Use for free with AWS Builder ID」または組織の「AWS IAM Identity Center」を選択してログインを完了。
* **クイックスタート**:
  * エディタ上で関数名やコメント（例: `# Create an S3 client and list buckets`）を入力すると、灰色のインライン候補が表示されるので `Tab` キーで確定。
  * コンソール画面右上またはIDEのQパネルを開き、「本番環境のEC2インスタンス健全性とCPU使用率の推移をチャートで表示して」と入力し、可視化ダッシュボードの出力を確認。

## **6. 特徴・強み (Pros)**

* **AWS運用・インフラとの圧倒的な親和性**: AWS SDK, CDK, CloudFormationの構文理解が極めて深く、2026年10月のアップデートによりコンソール上で直接ダッシュボードや異常検知チャートを描画できる唯一無二の運用監視アシスタント。
* **実績豊富なレガシーコード自動変換**: Java 8/11からJava 17/21へのアップグレードなど、工数のかかる言語移行タスクを隔離コンテナで自動ビルド・検証まで完結できる強力なモダナイゼーションエンジン。
* **堅牢なエンタープライズセキュリティ**: IAM Identity Centerとの深い統合、きめ細やかな権限管理、ユーザーコードをモデル学習に利用させないデータ保護設定に対応。
* **既存ユーザー向け無料枠の寛容さ**: 個人開発者向けのFree Tierにおいて、コード補完だけでなく月間一定回数のエージェント機能やセキュリティスキャンが無償で提供されている。

## **7. 弱み・注意点 (Cons)**

* **2027年4月末サポート終了（End-of-Support）への移行必須**: 2026年5月15日に新規登録がブロックされており、2027年4月30日にはIDEプラグインを含むすべてのサポートが完全終了する。利用者は期日までにスペック駆動開発環境「Kiro」への移行を完了しなければならない。
* **IDE向け新機能開発の凍結・縮小**: 開発リソースがKiroへ全面的にシフトしているため、エディタ拡張機能としてのアップデートは保守中心となり、競合製品のような最先端IDE機能の追加は期待できない。
* **AWS外の汎用Web開発における精度**: React, Vue, フロントエンドUIフレームワーク、一般的なアルゴリズム実装などAWS以外のドメインにおいては、GitHub CopilotやCursorと比較して補完精度や文脈把握力が劣る場合がある。
* **日本語対応の局所性**: チャット対話は日本語で行えるものの、生成されるコンソールダッシュボードの診断ラベルや詳細なドキュメントの一部は英語表記がベースとなっている。

## **9. 導入実績・事例**

* **導入企業**: BT Group, National Australia Bank (NAB), Toyota Connected, Takeda Pharmaceuticals, Safe Software, Eviden など。
* **導入事例**:
  * **BT Group**: 数万行におよぶJavaコードのバージョンアップグレードにおいてAmazon Qのコード変換を活用し、通常数ヶ月を要するモダナイゼーション期間を数週間に短縮。数千万円規模の開発工数削減を達成。
  * **National Australia Bank (NAB)**: 開発者の日常的なコーディング支援およびAWSベストプラクティスに基づいたインフラテンプレート生成に導入し、開発サイクルの迅速化を実現。
* **対象業界**: 通信、金融、ヘルスケア、製造、クラウドネイティブなWebサービス企業など、AWSを本番運用しているエンタープライズ企業。

## **11. エコシステムと連携**

### **11.1 API・外部サービス連携**

* **API**: Amazon Q Developer API経由で自社パイプラインへの組み込みが可能。
* **外部サービス連携**:
  * **開発環境**: Visual Studio Code, JetBrains IDEs, Visual Studio, AWS Cloud9 (レガシー)
  * **バージョン管理・CI/CD**: GitHub（Pull Request対話連携）、AWS CodePipeline
  * **チャットツール**: Slack, Microsoft Teams（AWS Chatbot連携）
  * **ターミナル**: Kiro CLIへの機能統合

### **11.2 技術スタックとの相性**

| 技術スタック | 相性 | メリット・推奨理由 | 懸念点・注意点 |
|:---|:---:|:---|:---|
| **AWS SDK / CDK / CloudFormation** | ◎ | 最適化されたモデルによる高精度な補完・構文検証・設定ミス検知 | 特になし |
| **Java (Spring Boot等)** | ◎ | バージョンアップグレード変換機能が極めて成熟 | 一部複雑な独自フレームワークは手動調整要 |
| **.NET (C#)** | ◯ | WindowsからLinuxへのマイグレーション支援 | 一部高度なGUIライブラリ変換には非対応 |
| **Python / TypeScript** | ◯ | AWS Lambdaやサーバーレスアプリ開発に標準対応 | 汎用WebロジックではCursor等に優位性 |
| **Go / Rust** | △ | 一般的な構文補完には対応するが変換支援等は対象外 | AWS特有の恩恵はSDK補完中心に留まる |

## **12. セキュリティとコンプライアンス**

* **認証**: AWS IAM Identity Centerによる企業向けSAML 2.0 / SSO統合、多要素認証（MFA）、個人向けAWS Builder ID認証に対応。
* **データ管理**: Pro Tierでは顧客の入力コードや対話履歴を基盤モデルの再学習に一切使用しないポリシーを明示。データ転送時・保存時のTLS/AES-256暗号化を徹底。
* **準拠規格**: SOC 1/2/3, ISO/IEC 27001, ISO/IEC 27017, ISO/IEC 27018, HIPAA, GDPRなど、AWSの主要なエンタープライズコンプライアンス要件に準拠。

## **13. 操作性 (UI/UX) と学習コスト**

* **UI/UX**: 
  * **AWSコンソール**: 画面右側にスライド展開するチャットパネルで直感的に操作可能。2026年10月のアップデートにより、テキストだけでなく表、ヘルスステータス、インタラクティブな時系列グラフがシームレスに描画され、一目で状況を把握できる。
  * **IDE**: 標準的なAI拡張機能と同様のキーバインド（Tabでの採択、Cmd/Ctrl+Iでのインライン指示）で違和感なく操作可能。
* **学習コスト**: 一般的なチャット型アシスタントと同様に自然言語で指示できるため導入初期の学習コストは低い。ただし、2027年4月のEOLに伴う「Kiro」への移行に際しては、スペック駆動開発（SDD）という新しい開発パラダイムの習得が必要となる。

## **14. ベストプラクティス**

* **効果的な活用法 (Modern Practices)**:
  * **コンソール運用可視化の活用**: インフラ障害やアラート発生時に、コンソールチャットから「過去24時間の関連リソースのメトリクス異常とステータスを可視化して」と指示し、即座にダッシュボードを自動生成させる。
  * **Javaの計画的アップグレード**: 2027年4月のサービス終了前に、未着手のJava 8/11資産をCode Transformation機能を用いてJava 17/21へと前倒しで一括マイグレーションする。
  * **Kiro環境への早期並行検証**: 既存のQ Developerの利用を継続しつつ、チーム内でKiroおよびKiro CLIの試験導入を開始し、SDDワークフローへの順応を進める。
* **陥りやすい罠 (Antipatterns)**:
  * **サービス終了の直前まで移行を放置する**: 2027年4月末でプラグインが動作しなくなるため、直前の駆け込み移行とならないよう段階的なスケジュールを組む必要がある。
  * **非推奨・削除済みコマンドの利用**: 過去のドキュメントに記載されているGitLabクイックアクション（`/q transform`, `/q dev`, `/q test`）は既に廃止されているため、最新のGitHub連携やKiro CLIを利用すること。

## **18. 総評**

* **総合的な評価**:
  Amazon Q Developerは、AWS SDK/CDKの補完やJava等のレガシー言語自動変換において確固たる地位を築き、さらに2026年10月にはAWSマネジメントコンソール上で数百のAPIを横断した動的ヘルスダッシュボード・時系列チャート描画を実現するなど、クラウド運用アシスタントとして大きな進化を遂げました。しかしながら、2026年5月の新規受付停止と2027年4月30日のEnd-of-Support（サポート終了）が正式にアナウンスされており、ツール単体としては「終息と移行のフェーズ」に位置付けられます。
* **推奨されるチームやプロジェクト**:
  すでにAmazon Q Developerのアカウントを保有している既存のAWS開発チーム。特に、オンプレミスや古いAWS環境上に残るJava 8/11等のレガシーシステムを2027年4月の期限までに最新バージョンへモダナイズしたいチームや、AWSマネジメントコンソール上での障害切り分けを効率化したいインフラ運用・SREチームに推奨されます。
* **選択時のポイント**:
  新規登録が締め切られているため、これから新規にAI開発支援を導入するプロジェクトでは最初から後継ツール「Kiro」を選択すべきです。現在利用中のチームにおいても、IDE上でのコーディング支援機能は速やかにKiro（およびKiro CLI）へとシフトさせつつ、Amazon Q Developerが持つ強力な自動コード変換機能やコンソール可視化機能を有効期限内にフル活用するというハイブリッドな移行戦略が最適解となります。
