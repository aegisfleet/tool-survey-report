# **OpenDots 調査レポート**

## **1. 基本情報**

* **ツール名**: OpenDots
* **ツールの読み方**: オープンドッツ
* **開発元**: CopilotKit (Tawkit, Inc.)
* **公式サイト**: [https://www.copilotkit.ai/opendots](https://www.copilotkit.ai/opendots)
* **関連リンク**:
  * GitHub: [https://github.com/CopilotKit/OpenDots](https://github.com/CopilotKit/OpenDots)
  * ドキュメント: [https://docs.copilotkit.ai/](https://docs.copilotkit.ai/)
* **カテゴリ**: AIエージェント
* **概要**: OpenDotsは、テキスト、音声通話、Slack間でシームレスに機能する常時稼働のAI「Dot（ドット）」を作成・運用するためのオープンソーステンプレートです。各Dotには専用のコンピュータ環境が与えられ、ユーザーと協調しながら作業を進めることができます。

## **2. 目的と主な利用シーン**

* **解決する課題**: アプリケーション内に高度なAIエージェントを組み込む際のインフラやUIの複雑さを解消し、永続的で状態を持つAIアシスタントを素早く構築すること。
* **想定利用者**: アプリケーション開発者、社内ツール開発チーム、AIエージェントを活用したいスタートアップ。
* **利用シーン**:
  * 調査や執筆など、特定の役割を持つ専門的なAIアシスタントを複数運用する。
  * ユーザーのSlackチャンネルや音声通話にAIを参加させ、非同期・同期の双方で業務をサポートする。
  * ブラウザ操作やファイル編集をAIに代行させ、その過程をチャット上で可視化・承認するワークフローの構築。

## **3. 主要機能**

* **Spaces（スペース）とPages（ページ）**: 作業ドキュメントを保存・管理する場所。視覚的なエディタ、Markdownサポート、変更の競合を防ぐ自動保存機能を備えています。
* **Specialist Dots（専門特化エージェント）**: 役割、指示、利用可能なツールを設定して個別のエージェント（Dot）を作成可能。リサーチャーやライターなど、用途に応じたカスタマイズが可能です。
* **Dot computers（エージェント専用コンピュータ）**: 各Dotは、独立したブラウザプロファイルやファイルシステムを持つ「コンピュータ」を使用でき、その操作状況はチャット上でリアルタイムに確認できます（OpenBot基盤）。
* **Human-in-the-loop（承認フロー）**: AIが作成したドラフトを保存する前に、ユーザーに承認（Approve & save）または拒否（Decline）を求めるプロセスを挟むことができます。
* **マルチチャネル対応（テキスト・通話・Slack）**: Webアプリ上のテキストチャットだけでなく、WebRTCを利用した音声通話や、Slack連携（Channels SDK）を通じて同じエージェントとやり取りが可能です。
* **バックグラウンド実行**: 定期的なタスクをスケジュールし、サーバーサイドで元の会話の文脈を保ちながら実行することができます。

## **4. 動作原理・システム構成**

* **アーキテクチャ**: サーバー・クライアント型およびコンテナベースのハイブリッド構成。バックエンドでAIと各種ツールが動作し、フロントエンド（React SDK）と通信します。
* **主要コンポーネントとデータフロー**:
  * フロントエンド（Webアプリ）は、CopilotKitランタイムを介してエージェントと通信します。
  * エージェントのUI/UXは、AG-UIプロトコルを使用して、ストリームメッセージ、ツール呼び出し、エージェントの状態を画面に同期させます。
  * Slack連携は「Channels SDK」で管理され、音声通話（Realtime speech）のデータも同様にコンピュートブリッジを経由してエージェントに渡されます。
  * エージェントの操作環境（ブラウザ、ファイル、シェル）は「OpenBot」によるコンテナ環境で隔離・管理されます。
* **特筆すべき要素技術**:
  * **AG-UI**: エージェントとUI層をつなぐオープンプロトコル。
  * **TanStack AI**: モデルストリーミングとサーバーサイドツールの実行を管理。
  * **CopilotKit Intelligence**: スレッド管理や状態の永続化を担当。

## **5. 開始手順・セットアップ**

* **前提条件**:
  * Node.js 24 および npm
  * Git
* **インストール/導入**:

  ```bash
  $ git clone https://github.com/CopilotKit/OpenDots.git
  $ cd OpenDots
  $ npm ci
  $ cp .env.example .env
  $ npm run dev
  ```

* **初期設定**:
  * 上記のコマンドでローカルサーバー（http://127.0.0.1:5173）が起動します。
  * サービス（AIモデル等）を接続する前に、ローカル環境でSpaceの作成やDotの設定を試すことができます。
  * 実際にチャットを開始するには、`.env`ファイルに会話やモデルの設定（APIキーなど）を追加します。Slack連携や通話機能、ブラウザサービスを利用する場合は別途セットアップが必要です。

## **6. 特徴・強み (Pros)**

* **高い拡張性とカスタマイズ性**: 完成された製品ではなく「テンプレート」として提供されるため、自社の要件に合わせてUIからインフラまで自由に変更可能です。
* **独立した実行環境**: エージェントごとにコンテナ化されたコンピュータ環境（OpenBot）が割り当てられるため、セキュアで独立したタスク実行が可能です。
* **人間主体の制御**: Human-in-the-loopの設計思想により、AIの実行結果を保存・適用する前に必ず人間の承認を挟む安全なワークフローが構築できます。
* **多様なインターフェース**: Web UIだけでなく、Slackや音声通話からでも同一の文脈でエージェントを利用できます。

## **7. 弱み・注意点 (Cons)**

* **開発アルファ段階**: 現状はアルファ版のテンプレートであり、マルチユーザー機能（共有編集や招待）などは未実装（今後の実装予定）です。
* **インフラ運用のハードル**: 自己ホスト型であるため、コンテナの管理、AIプロバイダーのAPIキー管理、Slackアプリの構成など、運用には一定の技術的知識が要求されます。
* **日本語対応の状況**: 基本的なUIやドキュメントは英語ベースです。ただし、バックエンドのLLM（OpenAI互換モデル等）が日本語をサポートしていれば、日本語での指示や出力は可能です。

## **12. セキュリティとコンプライアンス**

* **認証**: テンプレート自体の認証機能はミニマムであり、プロダクション環境ではユーザー自身で認証プロバイダー（OAuth等）を統合する必要があります。
* **データ管理**: 各Dotのブラウザプロファイルやファイルはコンテナ内に隔離されます。サービス用の認証情報（クレデンシャル）はサーバーサイドに留まり、クライアントのブラウザには露出しない設計になっています。
* **準拠規格**: オープンソースソフトウェアであり、特定のコンプライアンス認証は取得していません（ホスティング環境に依存します）。

* **学習コスト**: テンプレートをカスタマイズするには、React、Node.js、Docker、CopilotKitの知識が必要となるため、エンジニア向けであり学習コストは中〜高程度です。

## **14. ベストプラクティス**

* **効果的な活用法 (Modern Practices)**:
  * 役割を細分化する: 「リサーチャー」「ライター」のように、Dotごとに明確な役割とツール権限を付与し、それぞれの責務を分離することで精度の高い結果を得る。
  * スケジュール機能の活用: バックグラウンドでの定期的な情報収集などを設定し、常に最新の情報をSpacesに蓄積させる。
* **陥りやすい罠 (Antipatterns)**:
  * 開発初期段階での本番導入: アルファ版であり、マルチユーザー機能などが不足しているため、そのまま大規模なチームで本番運用するのは避けるべきです。
  * 権限の過剰付与: すべてのDotにシェル実行や全ファイルアクセスの権限を与えると、意図しない破壊的変更のリスクが高まるため、最小権限の原則に従う必要があります。

## **18. 総評**

* **総合的な評価**:
  * OpenDotsは、CopilotKitとAG-UIの強力な基盤の上に構築された、非常に野心的なオープンソースのAIエージェントテンプレートです。各エージェント（Dot）に独立したコンピュータ環境を与え、テキストチャットだけでなく音声やSlackを通じてシームレスに連携できる点は、次世代のAIアシスタントの形を示しています。アルファ版のため未成熟な部分もありますが、カスタマイズの自由度は非常に高いです。
* **推奨されるチームやプロジェクト**:
  * AIエージェントを自社プロダクトや社内ツールに深く組み込みたい開発チーム。インフラやReactの知識があり、ベースとなるテンプレートを自社の要件に合わせて拡張できるエンジニアリング組織。
* **選択時のポイント**:
  * 既存のノーコードプラットフォーム（Difyなど）では要件を満たせない、あるいはエージェントに独自の実行環境（ブラウザ操作やファイル操作）を与え、かつその挙動を細かくコントロール・可視化したい場合に、強力な選択肢となります。
