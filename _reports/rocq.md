# **Rocq 調査レポート**

## **1. 基本情報**

* **ツール名**: Rocq (旧名: Coq Proof Assistant)
* **ツールの読み方**: ロック
* **開発元**: Inria / Rocq Team
* **公式サイト**: [https://rocq-prover.org/](https://rocq-prover.org/)
* **関連リンク**:
  * GitHub: [https://github.com/rocq-prover/rocq](https://github.com/rocq-prover/rocq)
  * ドキュメント: [https://rocq-prover.org/docs](https://rocq-prover.org/docs)
* **カテゴリ**: 定理証明ツール
* **概要**: Rocq（旧名: Coq）は、高度な依存型を持つインタラクティブな定理証明アシスタントおよび関数型プログラミング言語である。数学的定理の証明や、ミッションクリティカルなソフトウェア・ハードウェアの形式検証などに利用される。

## **2. 目的と主な利用シーン**

* **解決する課題**: ソフトウェアやハードウェアの仕様に対する動作の正当性を数学的に証明し、バグの混入を原理的に防ぐ。数学の未解決問題や複雑な定理の機械的証明を可能にする。
* **想定利用者**: コンピュータサイエンス・数学の研究者、形式検証を必要とするソフトウェアエンジニア、教育機関の学生。
* **利用シーン**:
  * C言語コンパイラ（CompCertなど）の安全性の証明と検証
  * 暗号化アルゴリズムやプロトコルの形式的安全性証明
  * 数学（四色定理など）の証明の機械的検証と形式化

## **3. 主要機能**

* **Gallina仕様言語**: 依存型と高階論理を組み合わせた、プログラムの仕様記述および数学的定理記述のための言語。
* **対話的証明エンジン**: コマンド（タクティク）を通じて対話的に証明を展開し、小さな検証用カーネルによってその正確性を自動チェックする機能。
* **プログラム抽出（Extraction）**: 仕様と証明が完了したRocqのコードから、OCaml、Haskell、Schemeなどの言語の実行可能なプログラムを自動的に抽出する機能。
* **メタプログラミングと拡張性**: Ltac2などの組み込みメタプログラミング言語を利用し、証明の自動化や独自のドメイン特化言語（DSL）の埋め込みが可能。
* **多宇宙・多ソートの多相性**: 宇宙（Universe）やソートに関する多相性をサポートし、プレディカティブ・インプレディカティブの両方の宇宙での柔軟な記述が可能。
* **計算可能な型推論とReduction Engine**: `vm_compute` や `native_compute` などの効率的な評価エンジンにより、OCamlのランタイムを利用した高速な項の簡約が可能。

## **4. 動作原理・システム構成**

* **アーキテクチャ**: ローカル環境（またはWebブラウザ等のインターフェース上）で動作するクライアント型のプログラミング言語・証明環境。
* **主要コンポーネントとデータフロー**:
  * ユーザーはGallina言語を用いて定義や仕様、タクティクを用いて証明を記述する。
  * システムはこれをPCUIC（Polymorphic, Cumulative Calculus of Inductive Constructions）という理論に基づいた内部表現に変換する。
  * 証明はコンパクトな「証明チェックカーネル（Kernel）」によって妥当性が検証される。このカーネルはOCamlで記述されており、信頼すべきコードベース（Trusted Code Base: TCB）を最小限に抑えている。
* **特筆すべき要素技術**:
  * **PCUIC**: 帰納的構築の多相的・累積的計算（Polymorphic, Cumulative Calculus of Inductive Constructions）を基礎理論とする。
  * **SProp**: 定義レベルで証明の無関連性（Proof-Irrelevance）を保証する特殊なソート。

## **5. 開始手順・セットアップ**

* **前提条件**:
  * OCaml環境またはプラットフォームインストーラが実行できるOS（Linux, macOS, Windows）
* **インストール/導入**:

  ```bash
  # Rocq Platform経由でのインストール（opamを利用した一例）
  opam switch create rocq-9.2.0
  opam install rocq-prover
  ```

* **初期設定**:
  * 好みのテキストエディタ（VS Code, Emacs, Vimなど）に拡張機能やプラグイン（例: VsCoq, Proof General）をインストール。
* **クイックスタート**:
  * `.v`（Vernacular）ファイルを作成し、以下の「Hello World」に相当する証明を実行：
    ```coq
    Lemma add_0_r : forall n : nat, n + 0 = n.
    Proof.
      intros n. induction n.
      - reflexivity.
      - simpl. rewrite IHn. reflexivity.
    Qed.
    ```

## **6. 特徴・強み (Pros)**

* **高い信頼性と実績**: 小さなチェックカーネルのみを信頼すればよいアーキテクチャ（De Bruijn Criterion）を採用し、ACM Software System Award等を受賞する世界最高峰の信頼性。
* **コード抽出の柔軟性**: 証明付きの仕様から、バグのないOCamlやHaskellコードを生成し、実際のプロダクトに直接組み込むことが可能。
* **豊富なライブラリとエコシステム**: 巨大な数学ライブラリ（Mathematical Components）や分離論理フレームワーク（Iris）など、長年の蓄積によるエコシステムが存在する。
* **表現力の高い依存型システム**: 単純な型だけでなく、「特定の値を取る性質」などを型として定義できるため、非常に厳密な仕様を記述できる。

## **7. 弱み・注意点 (Cons)**

* **高い学習コスト**: 依存型理論や構成的数学の概念、タクティク言語の習得には相応の時間と学習が必要。
* **証明の保守性**: タクティクの記述方法によっては、コードの変更に対する証明の追従性（証明の堅牢性）が低下しやすい。
* **パフォーマンスの壁**: 極めて大規模な形式化においては、型チェックやコンパイルの時間が長くなる傾向がある。
* **日本語対応**: UIや公式ドキュメントは英語ベースであるため、日本語環境のみでの学習は難易度が高い。

## **9. 導入実績・事例**

* **導入企業/機関**: Inria, MIT, Google, University of Pennsylvania, Max Planck Institute, AbsInt, BlueRock, Formal Vindication 等
* **導入事例**:
  * **CompCert**: 完全な形式的証明が付けられたC言語コンパイラ。クリティカルな組み込みシステム（航空機、医療機器など）で利用される。
  * **四色定理・Feit-Thompson定理の証明**: 純粋数学における歴史的難問の証明を機械的に検証。
  * **Iris**: 並行プログラムやRust言語などの検証に用いられる分離論理の汎用フレームワークの基盤として活用。

## **11. エコシステムと連携**

### **11.1 API・外部サービス連携**

* **API**: OCamlで書かれた内部APIを持ち、プラグイン機構を通じてシステムの振る舞いを拡張可能。
* **外部サービス連携**: パッケージマネージャー（opamベース）を通じた数百の外部パッケージとのシームレスな統合。

### **11.2 技術スタックとの相性**

| 技術スタック | 相性 | メリット・推奨理由 | 懸念点・注意点 |
|:---|:---:|:---|:---|
| **OCaml** | ◎ | ネイティブ実装言語であり、コード抽出の標準ターゲット | 全く問題なく親和性が最高 |
| **Haskell** | ◯ | 関数型言語としてコード抽出の対象としてサポート | 遅延評価など一部のパラダイムの違いに注意 |
| **Rust / C** | △ | Irisなどを通じて検証対象とすることは可能 | コンパイラからの直接出力対象ではない |

## **12. セキュリティとコンプライアンス**

* **認証**: デスクトップアプリケーション/CLIツールのため非該当。
* **データ管理**: データはすべてユーザーのローカル環境（またはホスティングするCI/CDサーバー）に保存され、処理される。
* **準拠規格**: オープンソース（LGPL v2.1）であり、ソフトウェア自体の規格準拠の概念とは異なるが、生成・検証されたソフトウェアは最高レベルの安全基準（DO-178C等）の要件を満たすために使用される。

## **13. 操作性 (UI/UX) と学習コスト**

* **UI/UX**: コマンドラインツール（`coqc`, `coqtop`）に加え、CoqIDEという専用GUIや、VS Code/Emacsなどのエディタを通じたインタラクティブな証明体験が提供される。目標（ゴール）と現在利用可能な仮説が画面に表示される。
* **学習コスト**: 非常に高い。論理学と型理論の基礎知識が求められる。「Software Foundations」などのチュートリアルを通じて基礎から学ぶのが推奨される。

## **14. ベストプラクティス**

* **効果的な活用法 (Modern Practices)**:
  * ソフトウェア検証の場合、型に仕様をすべて詰め込むのではなく、実行可能な純粋関数を定義した上で、それとは独立して定理として証明を与える（Reflection等）スタイルが大規模検証では推奨される。
  * Ssreflect（Mathematical Componentsの一部）などの拡張タクティク言語を用いて、証明スクリプトをより堅牢かつ簡潔に記述する。
* **陥りやすい罠 (Antipatterns)**:
  * 大量の自動化タクティク（`auto`, `omega`, `lia` 等）を無秩序に適用すると、証明が壊れやすくなり、どこで失敗したかトレースしにくくなる。
  * 型推論の罠（Universe Inconsistencyなど）に陥らないよう、複雑な階層構造を作る際は慎重に設計する。

## **18. 総評**

* **総合的な評価**:
  Rocq（旧Coq）は、40年以上にわたる理論計算機科学の研究成果を結集した、世界最高水準の定理証明アシスタントである。その堅牢な理論基盤と、OCaml等の実行可能コードへの抽出機能により、単なる数学的証明の枠を超え、絶対にバグが許されないソフトウェアやコンパイラの構築において無二の存在感を示している。名前の変更（CoqからRocqへ）に見られるように、より産業応用に向けたリブランディングとエコシステムの整備が進んでおり、今後も形式検証の中心的な役割を担い続ける。
* **推奨されるチームやプロジェクト**:
  * コンパイラ、暗号アルゴリズム、OSカーネル、スマートコントラクトなど、ミッションクリティカルなシステムの開発チーム。
  * ソフトウェアの正当性を数学的に厳密に保証したい研究機関や先進的なテクノロジー企業。
* **選択時のポイント**:
  近年はLeanなどの新しい定理証明器も台頭しているが、既存の強力なライブラリ群（Iris, Mathematical Components等）や、CompCertのような圧倒的な産業実績を重視する場合は、依然としてRocqが第一の選択肢となる。
