# **MXC 調査レポート**

## **1. 基本情報**

* **ツール名**: MXC (Microsoft eXecution Container)
* **ツールの読み方**: エムエックスシー
* **開発元**: Microsoft
* **公式サイト**: [https://github.com/microsoft/mxc](https://github.com/microsoft/mxc)
* **関連リンク**:
  * GitHub: [https://github.com/microsoft/mxc](https://github.com/microsoft/mxc)
* **カテゴリ**: 開発者ツール
* **概要**: MXCは、信頼できないコード（モデルの出力、プラグイン、ツールなど）を安全に実行するためのサンドボックス型コード実行システムです。OSネイティブのプロセスサンドボックスから完全なVMまで、複数の隔離バックエンドを統一されたモデルと型付きSDKで提供します。

## **2. 目的と主な利用シーン**

* **解決する課題**: 信頼できない第三者のコードやAIの生成コードを、ホストシステムに影響を与えずに安全に実行したいという課題。
* **想定利用者**: アプリケーション開発者、プラットフォームエンジニア、セキュリティエンジニア
* **利用シーン**:
  * AIモデルが生成したコードの安全な実行とテスト
  * サードパーティ製プラグインやツールのサンドボックス環境での実行
  * マルチプラットフォームでの安全なコード評価・検証環境の構築

## **3. 主要機能**

* **クロスプラットフォーム対応**: Windows、Linux、macOSをサポートし、プラットフォームに適した隔離バックエンドを提供します。
* **JSONベースの構成**: バージョン管理されたコンテナ作成リクエストとセキュリティポリシーをJSONで定義可能です。
* **複数の隔離バックエンド**: ProcessContainer、Windows Sandbox、LXC、Bubblewrap、Seatbelt、MicroVM (Nanvix)、Hyperlight、IsolationSession、WSLCなど、多様なバックエンドを利用できます。
* **ポリシーベースのサンドボックス**:
  * **ファイルシステムポリシー**: 読み取り専用、読み書き可能、拒否パスリストを設定できます。
  * **ネットワークポリシー**: プロキシサポート、アウトバウンド制御、ホストフィルタリングが可能です。
  * **UIポリシー**: クリップボード、ディスプレイ、GUIアクセス制御に対応しています。
* **コンテナライフサイクル操作**: 永続的なコンテナのプロビジョニング、開始、実行、停止、プロビジョニング解除を管理できます。
* **多様なSDK**: Rust、.NET、Node.js向けの型付きSDKを提供し、バージョン管理されたAPIを通じてコードから直接利用できます。
* **診断機能**: コンテナ内でのアクセス拒否の失敗を理解し、ポリシーを調整するためのツールや監査モードを備えています。

## **4. 動作原理・システム構成**

* **アーキテクチャ**: アプリケーションに組み込む（インプロセス）SDKと、それによって制御されるプラットフォーム固有の分離バックエンドの構成
* **主要コンポーネントとデータフロー**:
  * アプリケーションがMXC SDK（Rust、.NET、Node.js）を呼び出し、コンテナの種類、分離ルール、ワークロードコマンドを指定します。
  * SDKがリクエストを検証し、適切なバックエンド（ProcessContainer、WSLC、Bubblewrapなど）を選択します。
  * バックエンドが指定されたルールに従って分離された環境（コンテナ）でワークロードを起動し、実行結果をアプリケーションに返します。
* **特筆すべき要素技術**:
  * Windows上のプロセス分離（ProcessContainer、Windows Sandbox）
  * Linux上の名前空間ベースの分離（Bubblewrap、LXC）
  * macOS上のSeatbeltによる制限
  * ハイパーバイザーベースの軽量VM（MicroVM、Hyperlight）

## **5. 開始手順・セットアップ**

* **前提条件**:
  * Node.js 24以上（Node SDKの場合）
  * Rust 1.93以上（ソースからビルドする場合）
  * 各バックエンドに依存するプラットフォームツールチェーン
* **インストール/導入**:

  ```bash
  # Node.jsプロジェクトへの導入例
  npm install @microsoft/mxc-sdk
  ```

* **初期設定**:
  * インストールしたSDKをコードにインポートするだけで利用可能。特別なシステム設定は不要（一部バックエンドを除く）。
* **クイックスタート**:
  * 以下はNode.jsでの実行例です。

  ```typescript
  import { spawn, type ContainerRequest } from '@microsoft/mxc-sdk/v1';

  const request: ContainerRequest = {
    command: 'node -e "console.log(\'hello from container\')"',
    network: { egress: { default: 'deny' } },
    timeoutMs: 30_000,
  };

  const child = await spawn(request);
  ```

## **6. 特徴・強み (Pros)**

* **単一のAPIで複数プラットフォームに対応**: OSごとに異なるサンドボックス機構（Bubblewrap、Seatbelt、Windows Sandboxなど）の差異を吸収し、統一されたAPIで利用できます。
* **用途に合わせたバックエンドの選択**: 軽量なプロセスベースの隔離から、より強力なVMベースの隔離まで、要件に応じてバックエンドを選択できます。
* **きめ細かいポリシー制御**: ネットワーク、ファイルシステム、UIへのアクセスを宣言的なJSONポリシーで詳細に制御可能です。

## **7. 弱み・注意点 (Cons)**

* **環境ごとの依存関係**: 一部のバックエンド（WSLC、LXCなど）はホストシステムに特定のツールチェーンや機能がインストールされている必要があります。
* **ポリシー設定の難易度**: 安全なサンドボックスを構成するには、アプリケーションが実際に必要とするリソースを正確に把握し、適切なポリシーを記述する知識が求められます（ただし監査モードによるサポートがあります）。
* **日本語対応状況**: 公式ドキュメントやUIなどは基本的に英語での提供となっています。

## **12. セキュリティとコンプライアンス**

* **認証**: 該当なし（ローカルで実行されるライブラリのため）。
* **データ管理**: コンテナ内でのファイルI/Oやネットワーク通信は、指定されたポリシーによって厳密に制御・隔離されます。
* **準拠規格**: 特定のコンプライアンス認証（SOC2など）を取得しているわけではありませんが、セキュアな設計原則に基づいて開発されています。

## **13. 操作性 (UI/UX) と学習コスト**

* **UI/UX**: GUIは提供されておらず、CLIおよびコード（SDK）ベースでの操作となります。
* **学習コスト**: サンドボックスの概念や各バックエンドの特性を理解する必要があり、安全で実用的なポリシーを設計するためには一定の学習が必要です。ただし、監査モード（Audit mode）を活用することで、必要なポリシーの洗い出しを支援してくれます。

## **14. ベストプラクティス**

* **効果的な活用法 (Modern Practices)**:
  * **監査モードの活用**: 新しいワークロードをサンドボックス化する際は、まず `--audit` モードで実行して必要なアクセス権限（ファイル、ネットワーク等）を特定し、それに基づいて最小権限のポリシーを作成する。
  * **適切なバックエンド選択**: 開発時は軽量な `bubblewrap` や `processcontainer` を使用し、本番環境でより強力な隔離が必要な場合はVMベースのバックエンドを検討する。
* **陥りやすい罠 (Antipatterns)**:
  * **過剰な権限付与**: ポリシー設定を怠り、デフォルトの拒否リストを広げすぎる（例：ネットワーク全体を許可するなど）とサンドボックスの意義が失われます。
  * **監査モードのプロダクション利用**: `--audit` モードはサンドボックスのセキュリティを無効にするため、決して信頼できないコードの実行環境で使用してはいけません。

### **17.2 詳細比較**

| ツール名 | 特徴 | 強み | 弱み | 選択肢となるケース |

## **18. 総評**

* **総合的な評価**:
  MXCは、異なるOSや分離技術の差異を抽象化し、単一のSDKを通じて一貫したサンドボックス環境を提供する強力なツールです。特にAIアシスタントやLLMエージェントが生成したコードを安全に実行するための基盤として非常に有望であり、活発なアップデートによって実用性が高まっています。
* **推奨されるチームやプロジェクト**:
  AI駆動のツールやプラットフォームを開発しており、ユーザーから提供されたコードやAI生成コードをサーバーまたはローカルで安全に実行・評価する必要がある開発チームに強く推奨されます。
* **選択時のポイント**:
  既存のDocker等のコンテナ環境ではセキュリティやパフォーマンス面で要件を満たせない場合、またはアプリケーションに直接サンドボックス管理機能（インプロセス）を組み込みたい場合にMXCは有力な選択肢となります。
