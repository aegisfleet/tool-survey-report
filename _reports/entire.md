# **Entire 調査レポート**

## **1. 基本情報**

* **ツール名**: Entire
* **ツールの読み方**: エンタイア
* **開発元**: Entire Inc.
* **公式サイト**: [https://entire.com](https://entire.com)
* **関連リンク**:
  * GitHub: [https://github.com/entireio](https://github.com/entireio)
* **カテゴリ**: Gitホスティング
* **概要**: AIエージェントと人間が共にコードを書き、レビューし、デプロイするための次世代Gitホスティング・プラットフォーム。既存のPRに代わる「Trails」や、最大89倍高速なGitバックエンドを特徴とする。

## **2. 目的と主な利用シーン**

* **解決する課題**: 大量にコードを生成するAIエージェントのスピードに、既存のコードレビューやCIインフラが追いついていない課題。AIエージェントが過去の文脈（なぜそのように実装したのか等）を忘れてしまう問題。
* **想定利用者**: AIエージェントを活用してソフトウェア開発を行う開発チーム、エンジニア組織。
* **利用シーン**:
  * 大規模なAIエージェントを多数同時に走らせて開発を行う場合
  * エージェントが過去に出した結論やコンテキストを検索・再利用したい場合
  * 人間によるPRレビューの代わりに、ゴールベースでタスク管理を行う場合

## **3. 主要機能**

* **Trails**: 従来のプルリクエスト(PR)に代わる機能。アイデアからマージまでを一つのTrail（軌跡）として管理し、関連する複数リポジトリの変更や、その背景にあるエージェントのセッションをまとめて確認できる。
* **Code Hosting**: 分散型のGitネットワーク。エージェントがクローン・プッシュするトラフィックに最適化されており、最大でGitHubの89倍高速と謳っている。US, EU, Australia, Indiaなどのリージョンに対応し、GitHubからのミラーリングも可能。
* **Entire CLI**: 既存のGitワークフローのまま、あらゆるエージェント（Claude Code, Codex, Cursorなど）のセッションや推論過程をコミットと共に記録・検索できるCLIツール。
* **Agentic Search**: ターボパッファー（turbopuffer）をベースとした検索。BM25による正確なコード検索と、コミットやセッションログからのセマンティック検索を統合しており、トークン使用量を削減しつつ精度を上げる。
* **Continuous Memory (Session Storage)**: コードの変更内容だけでなく、「なぜその変更が行われたか」というプロンプト、意思決定、ツール呼び出し履歴などの文脈（セッション）を永続化し、次にエージェントが作業する際の知識として活用できる。
* **CI Integration**: エージェントの高速なプッシュに追従できるCIパイプライン連携（Buildkite, Depot等）。キュー待ち時間をなくし、自動レビューやエバリュエーションを即座に実行する。
* **Plugins**: Entireのエコシステムを開放し、CI、デプロイ、プレビュー、エージェントなどをプラットフォームに統合できる仕組み。

## **4. 動作原理・システム構成**

* **アーキテクチャ**: 分散型のGit互換データベース層を備えたネットワーク。中央集権的なレートリミットを排除し、並行して大量のエージェントが作業できるように設計されている。
* **主要コンポーネントとデータフロー**:
  * リポジトリのソースコードだけでなく、エージェントのインテント（意図）や制約、コンテキストなどを「バージョンコントロール」システムに直接記録する。
  * ブランチが更新されるとイベントストリームにイベントが発行され、差分やセッションログ、コミットメッセージがチャンク化されてturbopufferに保存（インデックス）される。これにより、コードとセマンティック（意味論）の両方の検索が可能になる。
* **特筆すべき要素技術**:
  * turbopufferを利用したハイブリッド検索（BM25とApproximate Nearest Neighbor）。
  * 分散型Gitネットワーク。リージョンごとにデータを持ち、レイテンシを下げるとともにデータのローカライゼーション（レジデンシー要件）にも対応している。

## **5. 開始手順・セットアップ**

* **前提条件**:
  * GitHubアカウントなど。
  * ターミナルからアクセス可能であること。
* **インストール/導入**:

  ```bash
  # CLIのインストール
  curl -fsSL https://entire.com/install.sh | bash
  ```

* **初期設定**:
  * 対象のリポジトリディレクトリ内で以下のコマンドを実行し、Entireを有効化する。
  ```bash
  entire enable
  ```
* **クイックスタート**:
  * セッションやコミット、チェックポイント、トランスクリプトを跨いで検索を行う。
  ```bash
  entire search "検索クエリ"
  ```
  * セッションを再開する。
  ```bash
  entire session resume
  ```

## **6. 特徴・強み (Pros)**

* AIエージェントを活用した開発において、単なるファイルホスティング以上の「文脈（推論やセッション）」の保存・共有を実現している。
* 圧倒的なパフォーマンス（Gitのプッシュ処理等が非常に高速）であり、エージェントが大量のコードをプッシュしてもボトルネックにならない。
* 既存のコード生成ツール（Claude Code, Cursorなど）とCLI経由で連携でき、ベンダーロックインが少ない。
* Trails機能により、PR単位ではなく目的（アイデア）単位で複数リポジトリの変更をまとめてレビューできる。

## **13. 操作性 (UI/UX) と学習コスト**

* **UI/UX**: Web UI（ダッシュボード）のほか、CLIツールが充実している。PRではなく「Trails」という新しい概念でレビュー等を行うため、画面構成はGitHubなどとは異なる。
* **学習コスト**: PR文化に慣れた開発者が「Trails」や「Continuous Memory」といった新しいワークフロー（エージェントとの協業）に適応するための学習は必要となる。CLIの使用感はGitに似ている。

## **14. ベストプラクティス**

* **効果的な活用法 (Modern Practices)**:
  * GitHubをメインリポジトリとして残しつつ、エージェント用の高速なプッシュ・テスト先としてEntireを「ミラーリング」として活用する。
  * `entire enable` を使って、ローカルのターミナルで実行するAIコーディングセッションの履歴を常にGitコミットと紐付けて保存し、将来のAgentic Searchに備える。
* **陥りやすい罠 (Antipatterns)**:
  * 単に高速なGitホストとしてだけ使い、CLIによるセッション記録（Continuous Memory）を利用しないと、Entire本来の「AIエージェントに文脈を共有する」強みが活かせない。

## **18. 総評**

* **総合的な評価**:
  * ソフトウェア開発においてAIエージェントが主力となりつつある現在、従来の人間向けのPR文化やGitのインフラでは処理しきれないという課題に真正面から取り組んだ非常に野心的なプラットフォームである。「コードの差分」だけでなく「推論の文脈」を保存するというアプローチは革新的。
* **推奨されるチームやプロジェクト**:
  * 既にClaude CodeやCursor、CodexなどのAIコーディングツールを日常的に駆使しており、AIが生成するコードのレビュー負担や過去の文脈共有に課題を感じている先進的な開発チーム。
* **選択時のポイント**:
  * GitHubと完全に置き換える必要はなく、ミラーリングとしてEntireを利用し、エージェントの作業領域・検索基盤としてEntireの強みを活かす形での導入検討が推奨される。
