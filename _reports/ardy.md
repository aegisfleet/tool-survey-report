# **ARDY 調査レポート**

## **1. 基本情報**

* **ツール名**: ARDY (Autoregressive Diffusion with Hybrid Representation for Interactive Human Motion Generation)
* **ツールの読み方**: アーディ
* **開発元**: NVIDIA
* **公式サイト**: [https://github.com/nv-tlabs/ardy](https://github.com/nv-tlabs/ardy)
* **関連リンク**:
  * GitHub: [https://github.com/nv-tlabs/ardy](https://github.com/nv-tlabs/ardy)
  * Hugging Face: [https://huggingface.co/nv-tlabs/ARDY](https://huggingface.co/nv-tlabs/ARDY)
* **カテゴリ**: 3D/VTuber
* **概要**: ARDYは、ハイブリッド表現を用いた自己回帰型拡散モデルであり、テキストプロンプトやスパースなキネマティック制約から、インタラクティブかつ高品質な人間の3Dモーションを生成します。

## **2. 目的と主な利用シーン**

* **解決する課題**: 従来の手作業によるアニメーション制作の負荷軽減と、リアルタイムなインタラクションが求められる環境（ゲーム、VR/ARなど）における高品質なモーション生成の両立。
* **想定利用者**: 3Dアニメーター、ゲーム開発者、VR/ARクリエイター、ロボティクス研究者。
* **利用シーン**:
  * ゲームやメタバース環境におけるアバターのリアルタイムモーション生成。
  * テキスト指示によるアニメーション制作のプロトタイピング。
  * ロボット（ヒューマノイド）の行動計画や制御（GEAR SONIC等との連携）。

## **3. 主要機能**

* **テキストからのモーション生成**: 自然言語のプロンプトを入力として、対応する人間のモーションを生成。
* **キネマティック制約に基づく生成**: 軌跡、ウェイポイント、手足の配置など、様々な空間的制約を反映したモーションの生成。
* **自己回帰的生成**: 前のフレームのモーション履歴と将来の制約を条件として、無限長のモーションを生成。
* **インタラクティブデモ**: ViserベースのブラウザUIを通じて、リアルタイムにプロンプトや制約を変更しながらモーションをプレビュー可能。
* **TensorRTアクセラレーション**: 高速な推論を実現するため、TensorRTによる最適化をサポート。
* **複数スケルトンのサポート**: "Core"（手を含む52関節）、"Soma"（全身65関節）、"G1"（Unitree G1ロボット用）など、複数のスケルトンモデルに対応。

## **4. 動作原理・システム構成**

* **アーキテクチャ**: 自己回帰型の条件付き拡散モデル。
* **主要コンポーネントとデータフロー**:
  * **入力**: テキストプロンプト（LLM2Vecによるエンコード）、過去のモーション履歴、および将来のキネマティック制約。
  * **処理**: ハイブリッド表現（1Dモーション軌跡と3Dジョイント位置の組み合わせ）を用いて拡散モデルがノイズを除去し、次のフレームのモーションを生成。
  * **出力**: ジョイントのローカル/グローバル回転、ルート位置、および足の接地情報を含むモーションデータ。
* **特筆すべき要素技術**:
  * テキストエンコーダーとしてLLM2Vecを使用。
  * オプションで、フットスケートを減らし制約への追従を向上させるポストプロセス（後処理）を適用可能。

## **5. 開始手順・セットアップ**

* **前提条件**:
  * Linuxシステム (Ubuntu 22.04 推奨)
  * NVIDIA GPU (12GB以上のVRAM、TensorRT使用時は24GB以上推奨)
  * CUDA 12.1+
* **インストール/導入**:
  ```bash
  git clone --recursive https://github.com/nv-tlabs/ardy.git
  cd ardy
  conda create -n ardy python=3.10
  conda activate ardy
  pip install -r requirements.txt
  ```
* **初期設定**:
  * Hugging Faceから自動的にモデルウェイトがダウンロードされます。
* **クイックスタート**:
  ```bash
  # インタラクティブデモの起動
  python scripts/interactive_demo.py

  # コマンドラインからの生成（例）
  python scripts/generate.py "A person walks in a circle."
  ```

## **6. 特徴・強み (Pros)**

* **高い柔軟性**: テキストだけでなく、軌跡や関節位置といった物理的な制約を組み合わせてモーションを制御可能。
* **リアルタイム性とインタラクティブ性**: TensorRTによる高速化と自己回帰型アプローチにより、ユーザーの入力に即座に反応するモーション生成を実現。
* **オープンなエコシステム**: コードと学習済みモデルが公開されており、研究や開発に容易に組み込める。

## **7. 弱み・注意点 (Cons)**

* **高いハードウェア要件**: 快適な動作やTensorRTの利用には、VRAM容量の大きいNVIDIA GPUが必要。
* **複雑なセットアップ**: TensorRTなどの環境構築には、CUDAやCuDNNのバージョン依存性があり、やや学習コストがかかる。
* **日本語対応の状況**: ドキュメントおよびプロンプト入力は基本的に英語が前提。

## **13. 操作性 (UI/UX) と学習コスト**

* **UI/UX**: Viserを用いたWebベースのインタラクティブデモが提供されており、タイムライン操作や3Dビューポートでの確認、パラメータ調整が直感的に行える。
* **学習コスト**: インストールや環境構築に関するPython/CUDAの知識が必要。UIの操作自体は比較的容易。

## **14. ベストプラクティス**

* **効果的な活用法 (Modern Practices)**:
  * インタラクティブな生成を繰り返す場合は、テキストエンコーダーを別プロセスで起動（`python scripts/run_text_encoder_server.py`）しておき、推論速度を向上させる。
* **陥りやすい罠 (Antipatterns)**:
  * VRAMが不足している環境で、Float32精度のテキストエンコーダーや巨大なモデルを使用すると、Out Of Memoryエラーが発生しやすい。Bfloat16などの利用を検討する。

## **18. 総評**

* **総合的な評価**:
  * ARDYは、テキストベースの指示と物理的な制約をシームレスに統合し、リアルタイムでのインタラクティブなモーション生成を実現する非常に優れたオープンソースツールです。
* **推奨されるチームやプロジェクト**:
  * ゲーム開発スタジオ、VR/ARコンテンツ制作チーム、およびヒューマノイドロボットの制御を研究するエンジニアリングチーム。
* **選択時のポイント**:
  * 高品質なモーションを自前で生成・調整したい場合に最適。ただし、快適に動作させるためのGPU環境（高いVRAM容量）が必須となる点に留意が必要です。
