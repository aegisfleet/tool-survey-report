# **Code Video Model 調査レポート**

## **1. 基本情報**

* **ツール名**: Code Video Model
* **ツールの読み方**: コードビデオモデル
* **開発元**: Code Video Model Team
* **公式サイト**: [https://code-video-model.github.io/](https://code-video-model.github.io/)
* **関連リンク**:
  * GitHub: [https://github.com/code-video-model/CodeVideoModel](https://github.com/code-video-model/CodeVideoModel)
* **カテゴリ**: AI動画生成
* **概要**: Code Video Modelは、テキストプロンプトから直接最終的な動画を生成するのではなく、間に「コード（Three.js）」による物理シミュレーションを挟むことで、物理的に正確で制御可能な動画を生成する新しいアプローチのAI動画モデル。

## **2. 目的と主な利用シーン**

* **解決する課題**: 従来のビデオ拡散モデルが抱える、物理法則の破綻、オブジェクトの配置や動きの制御の難しさ、カメラ軌道の不安定さといった「ブラックボックス」な生成プロセスを解決する。
* **想定利用者**: AI研究者、映像クリエイター、ゲーム開発者、ロボティクス研究者
* **利用シーン**:
  * アニメーション制作におけるプリビズ（Previs）作成
  * 物理法則に基づいたゲーム内のアセット動画生成
  * ロボットの軌道制御やシミュレーション動画の作成

## **3. 主要機能**

* **プロンプトからのThree.jsコード生成**: テキストプロンプトを受け取り、GPT-6などのLLMを用いてシーンを構成・アニメーション化するThree.jsのコードベースを生成する。
* **プロキシビデオとリファレンス画像の生成**: 生成されたコードをレンダリングし、構造を定義するプロキシビデオと、外観を定義するリファレンス画像（フレーム）を出力する。
* **Early-step Conditioning**: 動画拡散モデル（MiniMax-H3など）の生成初期段階のみにプロキシビデオの構造情報を条件付けとして与え、後半はドロップすることで、プロキシの平坦な見た目に引きずられずにリファレンス画像のリッチな外観を保った最終動画を生成する。
* **シーンの直接編集**: コードを介して生成されるため、生成後にオブジェクトの配置やカメラワークのコードを直接書き換えることで、正確な動画の編集（リターゲティング）が可能。

## **4. 動作原理・システム構成**

* **アーキテクチャ**: LLM（GPT-6等）とビデオ拡散モデル（MiniMax-H3等）を組み合わせたパイプライン構成。
* **主要コンポーネントとデータフロー**:
  1. ユーザーがテキストプロンプトを入力。
  2. LLMがThree.jsのコードを記述。
  3. コードがレンダリングされ、物理シミュレーションが反映された「プロキシビデオ（Proxy Video）」が生成される。
  4. プロキシビデオからリファレンス画像（Reference Image）が抽出、またはGPT-Image-2等の画像生成モデルで作成される。
  5. ビデオ拡散モデルが、プロキシビデオとリファレンス画像を条件として最終的な高画質動画を生成する。
* **特筆すべき要素技術**:
  * **Three.js**: 物理法則（カメラ配置、オブジェクトの運動方程式など）をコードとして明示的に計算・レンダリングするためのエンジン。
  * **Early-step Conditioning**: 拡散モデルのサンプリングステップにおいて、初期の構造形成フェーズでのみ動画の条件付けを適用するスケジューリング手法。

## **5. 開始手順・セットアップ**

* **前提条件**:
  * Ubuntu 22.04
  * CUDA 12.6対応のNVIDIAドライバ
  * Anaconda / Miniconda
* **インストール/導入**:

  ```bash
  git clone https://github.com/code-video-model/CodeVideoModel.git
  cd CodeVideoModel
  conda create -n cvm python=3.10 -y
  conda activate cvm
  conda install -c conda-forge "ffmpeg[version='>=6',build='gpl_*']" -y
  python -m pip install torch==2.7.1 torchvision==0.22.1 torchaudio==2.7.1 --index-url https://download.pytorch.org/whl/cu126
  python -m pip install -r requirements.txt
  python -m playwright install chromium
  ```

* **初期設定**:
  * LLM連携用のAPIキー（OPENROUTER_API_KEY等）を環境変数に設定。
* **クイックスタート**:
  * MiniMax-H3のチェックポイントをダウンロードし、同梱のサンプル（例: `tank_boarding`）を用いて動画生成スクリプトを実行する。

## **6. 特徴・強み (Pros)**

* 映像の骨格（カメラワーク、オブジェクトの動き）がコード（Three.js）で定義されるため、従来の生成AIでは困難だった厳密な物理制御や直接的な編集が可能。
* 物理エンジンによって動的に計算されるため、接地感（Grounding）などの物理法則に矛盾がない。
* プロキシビデオの生成自体は数秒〜1分未満と高速であり、イテレーションを回しやすい。

## **7. 弱み・注意点 (Cons)**

* 最終的な動画品質は、バックエンドで使用されるビデオ拡散モデル（MiniMax-H3等）の性能に依存する。
* 高度なシーン生成には強力なLLM（GPT-6等）へのアクセスが必要となり、APIコストが発生する可能性がある。
* ローカルで実行環境（CUDA対応GPU等）を構築するハードルがある。
* 公式ドキュメントやサポートは基本的に英語のみ。

## **14. ベストプラクティス**

* **効果的な活用法 (Modern Practices)**:
  * 一度に最終動画を生成しようとせず、まずはLLMにThree.jsコードを生成させ、ブラウザプレビューでカメラワークやオブジェクトの動きを確認・微調整（直接編集）してから、ビデオ拡散モデルに渡すパイプラインを構築する。
* **陥りやすい罠 (Antipatterns)**:
  * プロンプトだけで全てをコントロールしようとすること。Code Video Modelの強みは「コードによる直接編集」にあるため、プロキシ動画が意図と異なる場合はコードを修正する方が確実。

## **18. 総評**

* **総合的な評価**:
  * Code Video Modelは、現在の主流である「ブラックボックス型」のビデオ拡散モデルに対して、「コードと物理エンジン」を間に挟むことで制御性と物理的な正確性をもたらす画期的なアプローチを提示している。研究段階のプロジェクトではあるが、映像制作やシミュレーション分野におけるパラダイムシフトとなる可能性を秘めている。
* **推奨されるチームやプロジェクト**:
  * AI動画生成の新しいアプローチを検証したい研究チームや、ゲームアセット・シミュレータ等の厳密な物理制御が求められる開発プロジェクトに強く推奨される。
* **選択時のポイント**:
  * 単に手軽に動画を出力したいだけであれば既存のSaaS型生成AI（RunwayやLuma）が適しているが、カメラの軌道、オブジェクトの動き、重力などの物理法則を「コードとして完全に制御」した上で高品質な映像を出力したい場合には、現時点でCode Video Modelが最有力の選択肢となる。
