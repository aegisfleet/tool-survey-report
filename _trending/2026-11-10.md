## **2. 🚨 緊急セキュリティ情報**

### **NocoBase - AI従業員（AI Employee）機能における認可バイパスとプロンプト・ツール設定漏洩 (CVE-2026-125397 / GHSA-4g9p-3cc5-xh4q)**

- **🔰 ひとことで言うと**: 社内のAI業務システムにおいて、一般の社員が他部署の機密AIを勝手に動かしたり、AIに教えてある社外秘の指示文を盗み見たりできる危険な欠陥が見つかりました。
- **内容**: 拡張性の高いオープンソースのノーコード/ローコード開発プラットフォーム「NocoBase」の公式AIプラグイン（`plugin-ai`）において、サブエージェント（AI Employee）の権限判定ルーチンに起因する深刻な認可バイパス脆弱性（CVE-2026-125397）が公表されました。
  NocoBaseの `plugin-ai` では、組織内の特定ロールやユーザーに特化させた「AI従業員」を定義し、それぞれに固有のシステムプロンプトや実行可能なツール権限（データベース操作、外部API連携など）を割り当てる機能を提供しています。しかし、内部関数 `getAccessibleAIEmployee()` において、リクエストパラメータに含まれるユーザー名（username）の取り扱いに不備があり、セッション情報に基づく本来のロールフィルタリングが、呼び出し側から渡された任意のユーザー名によって上書き（オーバーライド）可能な実装となっていました。
  これにより、認証済みの攻撃者は `get-ai-employee` ツールを介して自身に割り当てられていないAI従業員のシステムプロンプトやツール構成を平文で取得できるほか、`dispatch-sub-agent-task` ツールを悪用して本来アクセス権のない特権AI従業員に指示を出し、管理者権限でのデータ改ざんや機密情報の窃取を実行することが可能です。
- **リスク度**: 高（CVSS v3.1スコア: 8.8）
- **📊 影響の大きさ**:
  - **影響を受ける人**: NocoBaseで `plugin-ai` を導入し、複数のユーザーや異なる権限ロールでAI従業員・サブエージェント機能を運用している全環境。
  - **悪用の容易さ**: 攻撃には通常のアカウントでのログインが必要ですが、APIツール経由で指定パラメータを送信するだけで成立するため、悪用は極めて容易です。
- **対象バージョン/環境**: NocoBase `plugin-ai` バージョン `2.1.0` から `2.2.41` まで。
- **対策・ステータス**: NocoBase開発チームはPull Request `#11009` にて、ユーザーコンテキストの検証ロジックを修正し、セッション由来の認証情報以外でのAI従業員スコープ上書きを禁止するパッチを適用しました。最新バージョンへアップデートすることで解消されます。
- **🛡️ まずやるべきこと**: NocoBaseの管理者は、`plugin-ai` を含むシステム全体を直ちに最新の修正バージョンへ更新してください。アップデートが完了するまでの間、不特定多数のユーザーがアクセスする環境では `plugin-ai` プラグインの一時的な無効化、またはサブエージェントディスパッチ機能の利用制限を検討してください。
- **詳細リンク**: [GitHub Advisory (GHSA-4g9p-3cc5-xh4q)](https://github.com/advisories/GHSA-4g9p-3cc5-xh4q) / [NVD (CVE-2026-125397)](https://nvd.nist.gov/vuln/detail/CVE-2026-125397)

以下の図は、一般ユーザーが認可チェックをすり抜け、本来権限のない特権AI従業員を不正に操作して機密データを持ち出す攻撃フローを示したスイムレーン図です。

### **Ghostscript - `-dSAFER` サンドボックス回避による任意コード実行 (CVE-2026-125396 / GHSA-hg3g-c775-3fpj)**

- **🔰 ひとことで言うと**: ドキュメントの変換や画像化を行う基本プログラムに重大な弱点があり、細工されたPDFファイルを読み込ませるだけで、サーバーやパソコンが丸ごと乗っ取られる恐れがあります。
- **内容**: PostScriptおよびPDFファイルのオープンソース処理エンジン「Ghostscript」において、安全保護機能である `-dSAFER` サンドボックスを完全に無効化し、ホストOS上で任意のシェルコマンドやネイティブコードを実行（RCE）できる深刻な脆弱性（CVE-2026-125396）が報告されました。
  問題は、フォント初期化処理を担う `gs_fonts.ps` 内の `.putgstringcopy` プロシージャに存在します。この処理がオペランド（引数）のデータ型を事前に厳格検証せずに、特権オペレータである `.forceput` を呼び出していました。攻撃者が細工したPostScriptまたはPDFドキュメントを処理させると、意図的に型エラー（Type Check Error）を発生させ、カスタムエラーハンドラ経由で特権の `.forceput` を奪取・復元できます。これにより、PostScriptの save/restore 状態管理をまたいだUse-After-Free（解放後メモリへの不正アクセス）が引き起こされ、メモリ破損を経て任意のネイティブコード実行に至ります。
  AIを活用したドキュメント検索（RAG: 検索拡張生成）システムや、アップロードされたPDFからテキスト・サムネイルを自動抽出するWebアプリケーションの多くが、内部的にGhostscriptやImageMagickを採用しているため、攻撃者にとって極めて魅力的な侵入経路となります。
- **リスク度**: 高（CVSS v3.1スコア: 8.8）
- **📊 影響の大きさ**:
  - **影響を受ける人**: Linux/macOS/Windows環境でGhostscriptを直接、またはImageMagick、Pythonライブラリ、各種ドキュメント変換パイプライン経由で利用しているすべてのシステム。
  - **悪用の容易さ**: 悪意を持って細工されたPDFやEPSファイルをアップロード・処理させるだけで発動するため、外部入力を受け付けるWebサービスでは遠隔から容易に悪用可能です。
- **対象バージョン/環境**: Ghostscript バージョン `10.08.0` 未満のすべてのバージョン。
- **対策・ステータス**: Ghostscript公式リポジトリ（ArtifexSoftware/ghostpdl）において、コミット `1484854e0c8ddfda1baa4ad4cd965b8a9790aa81` により `.putgstringcopy` のオペランド型検証が厳格化され、サンドボックス回避を防ぐパッチが適用されました。
- **🛡️ まずやるべきこと**: ご利用のLinuxディストリビューションのパッケージマネージャ（`apt`, `dnf`, `pacman` 等）またはDockerコンテナのベースイメージを直ちに最新版へ更新し、Ghostscriptを `10.08.0` 以降にアップデートしてください。アップデートが即座に行えない場合は、ImageMagickの `policy.xml` でPDF/PS/EPS/XPSフォーマットの処理を無効化する暫定措置を実施してください。
- **詳細リンク**: [GitHub Advisory (GHSA-hg3g-c775-3fpj)](https://github.com/advisories/GHSA-hg3g-c775-3fpj) / [Ghostscript Bugzilla #709684](https://bugs.ghostscript.com/show_bug.cgi?id=709684)

### **Kubeflow Pipelines - 共有パイプラインのRBAC認可バイパス (CVE-2026-88984) & 未検証URLフェッチによるSSRF (CVE-2026-88983)**

- **🔰 ひとことで言うと**: 機械学習の学習・処理を管理する共有基盤において、一般ユーザーが社内の共有パイプラインを勝手に削除・改ざんできたり、サーバーを踏み台にして社内ネットワークを覗き見できる脆弱性が見つかりました。
- **内容**: クラウドネイティブな機械学習オーケストレーション基盤「Kubeflow Pipelines」のAPIサーバーにおいて、2件の重要なセキュリティ脆弱性が公表されました。
  1. **共有パイプラインのRBACバイパス (CVE-2026-88984 / GHSA-ghgh-57qv-h687)**: マルチユーザー環境において、Kubeflow Pipelines APIサーバーはネームスペース（名前空間）を持たない共有・グローバルパイプライン（Shared Pipelines）に対する認可チェックを誤ってスキップしていました。このスキップ処理が読み取りだけでなく更新（Write）や削除（Delete）操作にも適用されていたため、認証を持つ任意のユーザーが、KubernetesのRBAC（ロールベースアクセス制御）権限を持たずに共有パイプライン定義やバージョンを書き換えたり削除したりすることが可能でした。改ざんされたパイプラインが他のチームや定期実行ジョブで実行された場合、攻撃者が指定した不正なコンテナがクラスタ上で起動する重大な二次被害につながります。
  2. **APIサーバーの未検証URL取得によるSSRF (CVE-2026-88983 / GHSA-f7vj-6669-qvv4)**: パイプラインパッケージの登録時に、呼び出し側が指定した任意の `pipelineURL` に対してAPIサーバーが送信先ホストの検証を行わずにHTTPリクエストを発行していました。これにより、クラスタ内部のメタデータサービスや本来外部から到達できない内部マイクロサービスへ不正な通信（ブラインドSSRF）を試行させることが可能です。
- **リスク度**: 高（CVE-2026-88984: CVSS 8.5） / 中（CVE-2026-88983: CVSS 5.3）
- **📊 影響の大きさ**:
  - **影響を受ける人**: マルチユーザー構成でKubeflow Pipelinesをホストし、複数チームでMLモデルの学習や推論パイプラインを共有運用している組織。
  - **悪用の容易さ**: Kubeflowクラスタへの通常アクセス権があれば、標準のAPI呼び出しを行うだけで共有アセットの改ざんや内部通信の誘発が可能です。
- **対象バージョン/環境**:
  - RBACバイパス: Kubeflow Pipelines `2.16.1` 未満
  - SSRF脆弱性: Kubeflow Pipelines `2.17.0` 未満
- **対策・ステータス**: RBACバイパスは `v2.16.1`（PR `#13288`）にて、共有パイプライン操作時にKFPシステムネームスペースに対する権限検証を強制する修正が施されました。SSRF脆弱性は `v2.17.0`（PR `#12750`）にてURLスキーム、許可ドメイン、IPアドレス解決の厳格な検証が導入されています。
- **🛡️ まずやるべきこと**: Kubeflow Pipelinesを運用するMLOpsエンジニア・インフラ管理者は、コンポーネントを最新版（`v2.17.0` 以降を強く推奨）へアップグレードしてください。即時更新が困難な場合は、ネットワークポリシー（NetworkPolicy）によりPipelines APIサーバーからのクラスタ内不要通信および外部アウトバウンド通信を遮断してください。
- **詳細リンク**: [Kubeflow Advisory (GHSA-ghgh-57qv-h687)](https://github.com/kubeflow/pipelines/security/advisories/GHSA-ghgh-57qv-h687) / [Kubeflow Advisory (GHSA-f7vj-6669-qvv4)](https://github.com/kubeflow/pipelines/security/advisories/GHSA-f7vj-6669-qvv4)

### **Ollama - v0.40.16 リリース（コーディングモデル「Ripple Preview」対応 & Apple Siliconメモリ27GiB削減）**

- **🔰 ひとことで言うと**: パソコン上でAIを動かす定番ソフトが、プログラミング専用AIのプレビュー版に対応し、Macでの動作時に使用メモリを最大27ギガバイトも減らして驚くほど軽くなりました。
- **👥 誰に影響があるか**: 自宅や職場のPC/MacでローカルLLMを動かしてコーディング支援や開発自動化を行っているすべての開発者。
- **新機能の概要**: ローカルLLM実行環境「Ollama」の最新バージョン `v0.40.16` が公開されました。本バージョンでは、Recursive Intelligenceが開発した自律型エージェントコーディング特化の65B高密度モデル「Ripple Preview（`ollama run ripple-preview`）」のプレビューサポートが追加されたほか、Apple Silicon（MシリーズMac）向けの大幅なメモリ最適化が施されました。さらにWindows on ARM環境におけるCUDA 13.5のサポートや、基盤となるllama.cppの最新追従が行われています。
- **技術的ブレークスルー**: 特に注目されるのが、大型モデル「Qwen3.8 Flash Next」をApple Silicon環境のUnified Memory（統合メモリ）上で実行する際の内部テンソル管理の刷新です。不要なバッファ割り当てとKVキャッシュ配置を根本的に再設計したことで、モデル実行時のメモリフットプリントが従来比で約27 GiB削減されました。これにより、従来はメモリ128GBのMac Studioでしか快適に動かなかった構成が、メモリ64GBクラスのMacBook Proでも余裕を持って動作可能になりました。また、`/v1/responses` エンドポイントにおいて従来発生していたサイレントな出力切り捨て（silent truncation）が廃止され、API利用時の予測可能性が大幅に向上しました。
- **開発フローへの影響**: Claude Code連携コマンド（`ollama launch claude`）において、指定したローカルモデルへ確実にルーティングされるよう挙動が安定化しました。機密性の高いソースコードを社外のクラウドAPIに送信できない現場でも、手元のMacで超高精度なエージェント型コーディング環境を安全・高速に構築できるようになります。
- **利用開始日/提供形態**: 2026年11月9日よりGitHubおよび公式サイトにて提供開始。無料のオープンソースソフトウェア。
- **公式サイト/リリースノート**: [Ollama v0.40.16 Release Notes](https://github.com/ollama/ollama/releases/tag/v0.40.16)

### **OpenAI Python SDK - v3.48.0 リリース（エージェントセッション用ストリーミング & gpt-6-rosalind対応）**

- **🔰 ひとことで言うと**: OpenAIの公式ライブラリが更新され、AIが思考しながらツールを使う過程をリアルタイムに画面へ表示できるようになり、次世代AIモデルへの接続準備が整いました。
- **👥 誰に影響があるか**: OpenAIのAPIを用いてチャットボット、自律型エージェント、業務自動化ツールを開発しているPythonエンジニア。
- **新機能の概要**: OpenAI公式のPythonクライアントライブラリ「`openai-python`」がバージョン `v3.48.0` にアップデートされました。本リリースでは、長時間に及ぶエージェントの自律実行セッション（Agent Sessions）において、途中経過や思考プロセス、ツール呼び出し引数をきめ細かくリアルタイム配信できる「Stream Options（ストリーム拡張）」が正式サポートされたほか、ベータ版Responses APIにおいて次世代フロンティアモデル「`gpt-6-rosalind`」の識別子とスキーマ定義が追加されました。
- **技術的ブレークスルー**: 従来のストリーミングAPIでは、LLMの生成テキストトークンはリアルタイム取得できたものの、複数ステップにわたるエージェントセッション（内部思考、関数呼び出し、外部ツールの実行待ち、結果の再解釈）のライフサイクル全体を単一のストリームコネクションで構造化ハンドリングすることが困難でした。新設された `stream_options` により、SSE（Server-Sent Events: サーバーからクライアントへデータを逐次送る仕組み）上でエージェントの状態遷移やスケジュール情報（`agent scheduling support`）が明示的なイベントとして分離配信され、フロントエンドでのローディング表示やリアルタイムログ描画の実装が劇的に簡素化されました。
- **開発フローへの影響**: エージェントが裏で何分も考え込んでユーザーを不安にさせる「沈黙の待ち時間」を完全に解消し、ユーザーに対して「今どのファイルを検索しているか」「どんな推論を行っているか」をリアルタイムに可視化するUIをわずか数行のコードで実装可能になります。

- **🔰 ひとことで言うと**: 市販のゲーム用パソコンに載っているグラフィックボードで、AIの計算速度をタダで最大2倍に引き上げる魔法のようなツールが登場しました。

- **注目の理由・背景**: NVIDIAの消費者向けGeForceグラフィックボードは、ハードウェア的には極めて高性能なTensor Coreを搭載しているものの、エンタープライズ製品との差別化のためにドライバレベルで半精度（FP16/BF16）やTF32の連続行列演算スループットに制限（いわゆるhalf-speed制限）がかけられていました。本プロジェクトは、オープンソース版NVIDIAドライバ（nvidia-open）の制御レジスタ設定とクロック管理ルーチンをリバースエンジニアリングし、安全マージンを保ちながらリミッターを解除することに成功。公開からわずか短期間で18,000スター以上を獲得し、世界中のローカルAIコミュニティで熱狂的な話題となっています。
- **主な機能・用途**:
  - FP16, BF16, TF32におけるテンソル演算スループットを最大2倍に向上（vLLMやOllamaでのトークン生成速度が大幅改善）。

- **主な機能・用途**:

  - トーン＆マナーの設定: プロダクトのターゲット層に応じたデザインガイドラインを自動策定。

- **他の類似ツールとの比較**: 単なる静的コード解析（Linter）とは異なり、LLMがデザインの文脈やユーザー体験（UX）を理解した上でコードを書き直すため、画一的ではない「プロダクト固有の個性を持ったUI」へ昇華させることができます。

## **7. 📖 用語解説**

| 用語 | 解説 |
|------|------|
| **RCE（遠隔コード実行）** | 悪意ある第三者が、ネットワーク経由で離れた場所にある他人のサーバーやパソコンに、勝手にプログラムを実行させる極めて危険な攻撃です。「留守中の家に外部からリモコンで侵入され、勝手に機械を操作される」ような状態を指します。 |
| **RBAC（ロールベースアクセス制御）** | ユーザー一人ひとりに個別設定するのではなく、「管理者」「一般社員」「閲覧専用」といった役割（ロール）ごとにシステムの操作権限を割り当てるセキュリティの仕組みです。 |
| **SSRF（サーバーサイド・リクエスト・フォージェリ）** | 攻撃者がサーバーを踏み台にして、本来は外部から見ることができない社内ネットワークや内部システムに対して通信を行わせる不正手法です。「社内の受付係を言いくるめて、部外者が立ち入れない金庫室の様子を見に行かせる」ような攻撃です。 |
| **MCP（Model Context Protocol）** | AIモデルと外部のツール（データベース、CADソフト、ファイル検索など）を標準化された共通のルールで接続するためのオープン仕様です。USBケーブルのように、異なるメーカーのAIとツール同士を簡単に繋ぐことができます。 |
| **Tensor Core（テンソルコア）** | NVIDIAのグラフィックボード（GPU）に搭載されている、AIの計算（巨大な行列の掛け算や足し算）に特化した超高速の専用計算ユニットです。通常の計算コアよりも圧倒的に速くAIを動かせます。 |
| **パラメトリックCAD** | 「幅10cm、穴の半径5mm」のように寸法や条件（パラメータ）を数値で決めて設計する3Dソフトです。後から「幅を15cmに」と数字を変えるだけで、全体の形が自動的にきれいに再計算されます。 |
| **AI Slop（AIスロップ）** | AIが自動生成したテキストやWebデザインにありがちな、「中身が薄いのに見た目だけ派手」「紫色のグラデーションや絵文字が多すぎて安っぽい」といった質の低い生成物の俗称です。 |
| **アイソメトリック（等角投影図）** | 縦・横・高さの軸を等しい角度（通常120度ずつ）で描き、斜め上から見下ろすように立体を表現する図面技法です。プラモデルの説明書やシミュレーションゲームの画面のようになじみやすく、構造を直感的に把握できます。 |
