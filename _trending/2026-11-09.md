本日（2026年11月9日）のAIおよびソフトウェア開発ツール業界では、急速に本番導入が進む「自律型AIエージェント」を取り巻く実行基盤のセキュリティ問題と、それを堅牢・実用的に支えるための新世代ハーネス（統制・オーケストレーション）ツールの躍進が鮮明となりました。

## **2. 🚨 緊急セキュリティ情報**

### **n8n - AIエージェントノードにおける認可バイパスと任意コマンド実行 (CVE-2026-65015 / GHSA-2q3r-8m6j-9679)**

- **🔰 ひとことで言うと**: 自動化ツール「n8n」で、本来は画面を見るだけのはずの人が、AIエージェントに命令を出して社内サーバーを裏から乗っ取れる危険があります。
- **内容**: ワークフロー自動化ツール「n8n」において、プロジェクトの閲覧権限（Project Viewer）しか持たないユーザーが、AIエージェントノードを経由してホストシステム上の任意コマンドを実行（RCE）できる深刻な認可バイパス脆弱性（CVE-2026-65015）が公表されました。
  n8nは近年のアップデートでLangChainを内包した高度な「AI Agent」ノードやツール実行ノードを標準提供しています。しかし、ワークフロー実行エンジンの内部ディスパッチ機構において、一般ユーザーからのテスト実行リクエストやチャットUI入力に含まれるノード識別子の検証が不十分でした。攻撃者はAPI経由で細工したメッセージを送信することで、実行権限のないはずの「Execute Commandノード（シェル実行）」や「Codeノード（JavaScript/Python実行）」をAIエージェントのサブツールとして強制的に呼び出し、サンドボックスを迂回してn8nコンテナおよびホストOS上で任意のシェルコマンドを実行可能です。これにより、ワークフロー内に保存されたデータベース接続文字列、OAuthトークン、クラウドプロバイダのクレデンシャルが完全に奪取される恐れがあります。
- **リスク度**: 緊急（CVSS v3.1スコア: 9.4）
- **📊 影響の大きさ**:
  - **影響を受ける人**: n8nのセルフホスト版（Community Edition / Enterprise）を複数ユーザー・複数権限ロールで共有運用し、AIエージェント関連ノードを有効化している全組織。
  - **悪用の容易さ**: 攻撃には最小限の閲覧アカウントが必要ですが、特別な攻撃ツールを必要とせず、標準のHTTPリクエストを送信するだけで権限昇格とコマンド実行が成立するため容易です。
- **対象バージョン/環境**: n8n `1.70.0` 未満の全バージョン。
- **対策・ステータス**: n8nセキュリティチームより修正パッチが適用された `v1.70.0` がリリースされました。ノードディスパッチ時の権限コンテキスト継承ロジックが根本的に見直され、セッション所有者のロールに基づきツール実行権限が厳格に拒否されるようになりました。
- **🛡️ まずやるべきこと**: Dockerやnpmでn8nをホストしている管理者は、直ちにコンテナイメージまたはパッケージを `v1.70.0` 以降にアップデートしてください。即時更新が難しい場合は、ワークスペース設定で「Execute Command」ノードのグローバル無効化（環境変数 `EXECUTIONS_PROCESS=main` かつコマンド実行ノードの制限）を実施してください。
- **詳細リンク**: [n8n Security Advisory (CVE-2026-65015)](https://github.com/n8n-io/n8n/security/advisories)

### **LangChain / LangGraph - チェックポイント逆シリアライズにおけるリモートコード実行 (CVE-2025-68664 / GHSA-c67j-w6g6-q2cm)**

- **🔰 ひとことで言うと**: AIの思考プロセスや記憶データを保存する仕組みに欠陥があり、細工されたデータを受け取るとサーバーが外部から遠隔操作される恐れがあります。
- **内容**: マルチエージェントオーケストレーション基盤「LangGraph」および「langchain-core」において、エージェントの会話状態（State）やチェックポイント（Checkpointer: 処理の途中経過保存機能）の復元処理に起因する重大なリモートコード実行（RCE）の脆弱性が特定されました。
  LangGraphでは、長時間動作するエージェントが一時中断した状態をPostgreSQL、Redis、SQLiteなどの外部永続化バックエンドにシリアライズ（データ変換）して保存し、次回呼び出し時に再構築（デシリアライズ）します。従来の復元ルーチンにおいて、特定のオブジェクトローダーが安全でないPythonオブジェクト復元（Pickleに類似した任意クラスインスタンス化ロジック）を許容する実装となっていました。外部からのプロンプトやWeb検索結果、あるいは共有データベース上に細工された状態ペイロードが混入した場合、エージェントが状態を復元した瞬間に任意のPythonコードがサーバー上で実行されてしまいます。
- **リスク度**: 緊急（CVSS v3.1スコア: 9.8）
- **📊 影響の大きさ**:
  - **影響を受ける人**: LangGraphのチェックポインタ（`PostgresSaver`, `MemorySaver`, `RedisSaver` など）を利用してステートフルなAIエージェントやマルチユーザー対応チャットボットを本番運用している全環境。
  - **悪用の容易さ**: 悪意あるセッションデータや細工された状態パラメータをAPI経由で送信することで、認証の有無を問わずトリガー可能な構成が存在します。
- **対象バージョン/環境**:
  - `langgraph` バージョン `0.2.70` 未満
  - `langchain-core` バージョン `0.3.38` 未満
- **対策・ステータス**: メンテナより安全なJSON/MessagePackスキーマへのデシリアライザ限定と、危険なクラス解決ルーチンの完全廃止を行った修正版（`langgraph >= 0.2.70`, `langchain-core >= 0.3.38`）が緊急リリースされています。
- **🛡️ まずやるべきこと**: Python環境（`uv`, `poetry`, `pip` 等）において `langgraph` および `langchain-core` のバージョンを確認し、直ちに最新バージョンへ更新してください。また、PostgreSQLやRedisに保存されている既存のチェックポイントテーブルに不審なレコードがないか監査ログを確認してください。
- **詳細リンク**: [LangChain Security Advisory (CVE-2025-68664)](https://github.com/langchain-ai/langgraph/security/advisories)

### **Cursor / VS Code AI拡張 - 間接的プロンプトインジェクションによるMCP設定ファイル改変とRCE (CVE-2025-54135)**

- **🔰 ひとことで言うと**: 危険な仕掛けがされたWebサイトや公開プログラムをAIに「解説して」と頼むだけで、パソコンに勝手に不正な裏口が作られてしまう危険があります。
- **内容**: AI特化型エディタ「Cursor」やVS Code向けAI拡張機能において、外部リポジトリのドキュメントやコードコメントを通じた間接的プロンプトインジェクション（Indirect Prompt Injection: 外部文書に隠された指示でAIを操る手法）により、Model Context Protocol（MCP）設定ファイルが不正に書き換えられる脆弱性（CVE-2025-54135）が報告されました。
  攻撃者は、GitHub上の公開リポジトリのREADMEやCSS/Markdownファイル内に、人間の目には自然に見えるがLLMには強力な指示として解釈される特殊なプロンプトを埋め込みます。開発者がそのリポジトリを開き、AIチャットやコード生成エージェントに対して「このプロジェクトの概要を教えて」などの一般的な指示を出した際、エージェントが隠し指示を読み取り、ローカル環境のMCP設定ファイル（例: `~/.cursor/mcp.json` や `.vscode/mcp.json`）を編集するツールコマンドを自律的に呼び出します。
  攻撃者のプロンプトによって設定ファイルに悪意ある外部MCPサーバーの起動スクリプト（リバースシェルを実行するNode.jsやPythonスクリプト）が追記されると、次回のエディタ起動時やツール実行時にバックグラウンドでスクリプトが自動実行され、開発者の端末が完全にリモート制御されます。
- **リスク度**: 高（CVSS v3.1スコア: 8.8）
- **📊 影響の大きさ**:
  - **影響を受ける人**: CursorやVS CodeでMCP機能を利用しており、オープンソースや社外の未検証コードをAIアシスタントに読み込ませているすべてのエンジニア。
  - **悪用の容易さ**: 攻撃者はリポジトリにテキストを配置して開発者に参照させるだけで成立し、開発者自身がAIの提案を疑わず承認してしまうソーシャルエンジニアリングと組み合わされるため危険です。
- **対象バージョン/環境**: Cursor `0.45.0` 未満、およびMCP設定自動同期を有効にした一部のVS Code拡張。
- **対策・ステータス**: Cursorチームより、エディタの設定ファイル（特にMCPサーバー定義ファイル）に対するエージェントの書き込み権限を厳格に制限し、変更時には独立した警告モーダルによる明示的ユーザー承認を義務付けるパッチ（Cursor `0.45.0` 以降）が配信されています。
- **🛡️ まずやるべきこと**: ご利用のCursorまたはVS Code拡張機能を直ちに最新版へ更新してください。また、`~/.cursor/mcp.json` などの設定ファイルをテキストエディタで開き、見覚えのない外部サーバーやコマンドが登録されていないか目視で確認してください。
- **詳細リンク**: [Model Context Protocol Security Guidelines](https://github.com/modelcontextprotocol/specification/security)

以下の図は、攻撃者がオープンソースのコードに罠を仕掛け、開発者がAIに要約を頼むことで端末が乗っ取られるまでの攻撃フローを示したスイムレーン図です。

### **New API - 0.0.0.0バインド迂回によるマルチモーダルSSRF脆弱性 (CVE-2026-42339)**

- **🔰 ひとことで言うと**: AI中継サーバーに細工した画像のリンクを送ると、社内の非公開サーバーやクラウドの管理者権限が盗まれる恐れがあります。
- **内容**: 複数の大規模言語モデル（LLM）APIを一元管理・中継する人気ゲートウェイ「New API」において、Server-Side Request Forgery（SSRF: サーバーに意図しない通信を行わせる攻撃手法）の脆弱性（CVE-2026-42339）が報告されました。
  マルチモーダルチャット機能において、ユーザーが画像のURLを指定した際、New APIのバックエンドは外部から画像バイナリをダウンロードしてモデルに転送します。内部IP（`127.0.0.1` や `10.0.0.0/8` など）へのアクセスを防ぐURLブラックリストフィルタが実装されていましたが、`http://0.0.0.0:80/` などのワイルドカードIP表現や、HTTP 302リダイレクト追従時の送信先IP再検証が欠落していました。
  攻撃者はこのバイパスを利用して、AWS/GCPのインスタンスメタデータエンドポイント（`http://169.254.169.254`）から一時的なIAMクレデンシャルを取得したり、社内ネットワーク内の非公開データベースや監視ツールを探索することが可能になります。
- **リスク度**: 高（CVSS v3.1スコア: 8.6）
- **📊 影響の大きさ**:
  - **影響を受ける人**: New APIを外部公開または共有環境で運用し、Vision/マルチモーダルモデルのエンドポイントを提供している全インフラ管理者。
  - **悪用の容易さ**: 通常のチャットリクエストに画像URLとして特定のアドレスを含めるだけで発火するため、攻撃の敷居は低いです。
- **対象バージョン/環境**: New API `v0.4.8` 未満のバージョン。
- **対策・ステータス**: 最新版 `v0.4.8` が公開されました。DNS名前解決後の実IPアドレスに対する厳格なプライベートIP/メタデータIP拒否チェックと、リダイレクト時のホップ先に対する再検証ロジックが追加されています。
- **🛡️ まずやるべきこと**: New APIのDockerコンテナイメージを直ちに `v0.4.8` 以上へ更新してください。また、AWS/GCP上で稼働している場合は、インスタンスのメタデータサービス（IMDSv2）へのホップ制限（Hop Limit: 1）を適用してコンテナからの不正参照を遮断してください。
- **詳細リンク**: [New API Releases (v0.4.8)](https://github.com/Calcium-Ion/new-api/releases)

### **PydanticAI - v2.0 正式リリース（ハーネスファースト設計と分散実行エンジン統合）**

- **🔰 ひとことで言うと**: エラーを起こしにくく信頼性の高いAIエージェントを、途中でサーバーが落ちても自動でやり直せる頑丈な構造で作れるようになりました。
- **👥 誰に影響があるか**: Pythonで生成AIアプリや自律エージェントを本番運用しているバックエンドエンジニア、データサイエンティスト。
- **新機能の概要**: Pythonの型定義ライブラリPydanticの開発チームが手掛けるエージェントフレームワーク「PydanticAI」が、大型メジャーアップデート「v2.0」を正式リリースしました。
  v2.0では設計思想を根本から刷新し、「ハーネスファースト（Harness-First: 実行統制優先）」を標榜しています。従来のスクリプト型エージェントループを脱却し、耐久性のある分散実行エンジン（Temporal、DBOS、Prefect、AWS Lambda等）とのネイティブ連携レイヤーを標準搭載しました。これにより、数十分〜数日間にわたって実行される長時間のエージェント処理がサーバー再起動やAPIタイムアウトに遭遇しても、最後の成功チェックポイントからミリ秒単位でロールバック・再開可能な「Durable Execution（耐久実行）」を型安全に実現できます。
  さらに、AnthropicのModel Context Protocol（MCP）のクライアントおよびサーバー機能をコアモジュールとして内包し、OpenTelemetry互換の分散トレーシングがデフォルトで動作するようになりました。
- **技術的ブレークスルー**: 従来はエージェントの永続化やリトライ処理、分散トランザクションを開発者が自前でRedisやCeleryを組み合わせて複雑なコードを書く必要がありました。PydanticAI v2.0では、Pythonの型ヒントとPydanticモデルで入力・出力・ツールのシグネチャを定義するだけで、実行基盤側が耐障害性と状態追跡を完全に保証する抽象化を実現しました。
- **開発フローへの影響**: プロトタイプから本番運用への移行リードタイムが劇的に短縮され、エージェントの暴走やクラッシュに伴うビジネスリスクを最小限に抑えられます。
- **利用開始日/提供形態**: 本日よりオープンソース（MITライセンス）として提供開始。`pip install -U pydantic-ai` で導入可能。
- **公式サイト/リリースノート**: [PydanticAI Documentation](https://ai.pydantic.dev/)

### **vLLM - v0.33.0 リリース（LibTorch Stable ABI移行とAgent-Aware PagedAttention）**

### **AIコード生成時代の「スロップスクワッティング（Slopsquatting）」対策**

AIコーディング支援（Claude Code、Cursor、GitHub Copilot等）が広く普及した現在、新たなサイバー攻撃手法として**「スロップスクワッティング（Slopsquatting: AIのハルシネーションを狙ったタイポスクワッティング攻撃）」**が深刻化しています。

LLMはコード生成時に、実際には存在しない架空のパッケージ名（例: `fastapi-auth-helpers` や `react-dynamic-modal-v2` など）を「それらしい名前」として自信満々に出力（ハルシネーション）することがあります。攻撃者はこうしたAIの出力傾向を調査し、AIが生成しそうな未登録パッケージ名をあらかじめnpmやPyPIに先回りして登録しておきます。開発者がAIの指示通りに `npm install` や `pip install` を実行した瞬間に、悪意あるコードが開発端末に感染します。

**現場で直ちに実践できる防衛Tips:**
1. **ロックファイルの厳格な運用**: 新規パッケージ追加時は、必ず公式ドキュメントやリポジトリ（スター数、コミット履歴、メンテナ情報）を人間の目で確認してからインストールしてください。
2. **パッケージマネージャーの監査設定**: `uv` や `pnpm` を使用し、依存関係の解決時に未検証の新規登録パッケージを警告するCIチェックを導入する。
3. **プロンプトでのライブラリ指定制限**: AIに指示を出す際、「標準ライブラリのみを使用せよ」「指定したライブラリ（例: Pydantic, Requests）以外の外部パッケージを勝手に追加するな」という制約をシステムプロンプトに明記する。

この課題に対し、エコシステム側も急速に進化しています。本日登場したPydanticAI v2.0のDurable Execution（耐久実行）や、AgentFSのCopy-on-Write仮想化、Git AIのプロンプト監査ログ機能などは、いずれも「自律エージェントが暴走したりクラッシュしたりしても、確実に制御下に置き、安全に巻き戻せる環境」を提供する技術です。

エンジニアおよび開発組織は、最新モデルの導入を急ぐだけでなく、AIツールに与える権限の最小化、MCP設定の厳格な監査、そして安全なサンドボックス技術の積極的な導入を進めることが、2026年後半の開発競争において不可欠な生存戦略となります。

## **7. 📖 用語解説**

本日のレポートに登場した専門用語のうち、一般読者や初学者に馴染みが薄いものを分かりやすく解説します。

| 用語 | 平易な解説 |
|------|------------|
| **RCE（リモートコード実行）** | インターネット経由で、遠く離れた第三者のコンピュータを遠隔操作し、好きなプログラムを勝手に動かしてしまう非常に危険なサイバー攻撃のことです。 |
| **SSRF（サーバーサイド・リクエスト・フォージェリ）** | 外から直接アクセスできない会社の社内ネットワークに対して、公開されているWebサーバーを「踏み台」にして代わりに内部の情報を覗き見させる攻撃手法です。 |
| **MCP（Model Context Protocol）** | AIがパソコン内のファイルや外部のツール（データベースやブラウザなど）と安全にやり取りするための「共通の接続規格（USBのようなもの）」です。 |
| **間接的プロンプトインジェクション** | Webサイトの文章や公開プログラムの中に「AIに対する裏の命令」をこっそり隠しておき、それを読んだAIを騙して不正な動作をさせる攻撃のことです。 |
| **ハーネス（Harness）** | 競走馬の手綱や安全ベルトのように、暴走しやすい自律型AIにブレーキをかけ、決められたルールと安全な環境の中で正しく働かせるための制御の仕組みです。 |
| **CoW（Copy-on-Write: コピーオンライト）** | ファイルを編集する際、元の本物ファイルには手を触れず、変更した部分だけを別の下敷きに書き写す仕組みです。失敗しても下敷きを捨てるだけで一瞬で元に戻せます。 |
| **デシリアライズ（Deserialization）** | メモ帳や通信用に一列に並べられた文字列データを、プログラムが扱える元の複雑な「記憶（オブジェクト）」の形に復元する処理のことです。 |
