## **2. 🚨 緊急セキュリティ情報**

### **Broadcom / VMware — vCenter認証バイパスとESX遠隔実行を含む23件の脆弱性 (`VMSA-2026-0011`)**

> **🔰 ひとことで言うと**
> 企業の仮想サーバー群を管理するシステムで、パスワード確認をすり抜けて管理者権限を奪われたり、サーバー本体を遠隔操作されたりする深刻な弱点がまとめて23件見つかりました。
> 💬 *例えるなら：マンション全体のマスターキーを保管する管理室の裏口に鍵のかけ忘れがあり、誰でも中に入って全部屋のドアを開けられるような状態です。*
{: .callout-danger}

| リスク度 | 影響を受ける人 | 悪用のされやすさ | まずやるべき対策 |
| :---: | :--- | :--- | :--- |
| 🔴 **緊急** | **VMware vCenter Server / ESX (ESXi) / Workstation / Fusion / Tools / Avi Load Balancer 管理者** | ネットワーク経由で認証なしに到達可能（最大CVSS **9.8**） | **Broadcom公式アドバイザリを確認し、vCenter・ESXの修正パッチを即時適用** |

<details markdown="1">
<summary>🔍 技術的な仕組み・対象バージョン・対策コマンドを見る（エンジニア向け）</summary>

- **原因の仕組み**: 2026年11月24日、BroadcomはVMware製品群における計23件の脆弱性を修正するアドバイザリ `VMSA-2026-0011` を公開した。特に深刻なものは以下の通り。
  - **`CVE-2026-123903`（CVSS 9.8 / vCenter Server）**: VMware Directory Service（`vmdir`）における認証バイパス脆弱性。ネットワークアクセス権を持つ攻撃者が認証機構を回避し、システム全体の制御権を奪取できる恐れがある（現時点でゼロデイ悪用の報告はなし）。
  - **`CVE-2026-123910` / `CVE-2026-123911`（CVSS 9.8 / VMware ESX）**: ESX I/Oフィルターサービス（`IOFilterVP`、ポート9080）におけるヒープ境界外書き込みおよび解放済みメモリ使用（Use-After-Free）の脆弱性。ESXホスト上での任意コード実行（RCE）につながる。
  - **`CVE-2026-123912`（CVSS 9.3 / Workstation, Fusion, ESX）**: XHCI USBコントローラにおける境界外書き込み。仮想マシン内の管理者権限からホスト上のVMXプロセスとしてコード実行が可能になる。
- **対象製品**: VMware vCenter Server、VMware ESX（ESXi）、VMware Workstation、VMware Fusion、VMware Tools、VMware Avi Load Balancer、およびこれらを含む VMware Cloud Foundation / vSphere Foundation。
- **対策手順**:
  - 管理ネットワーク（特にvCenterの`vmdir`およびESXのポート9080）へのアクセス制限を再確認し、信頼できないネットワークから遮断する。
  - Broadcomのサポートポータルから各製品・バージョンに対応した最新パッチを適用する。
- **一次ソース**: [Broadcom Security Advisory - VMSA-2026-0011](https://support.broadcom.com/web/ecx/support-content-notification/-/external/content/SecurityAdvisories/0/39626)

</details>

### **Drupal Core — 導入用スクリプトの悪用によるサイト乗っ取りがCISA KEVに追加 (`CVE-2026-132165`)**

> **🔰 ひとことで言うと**
> Webサイト作成ソフト「Drupal」に最初から入っている初期設定用の画面を悪用し、外部の攻撃者がすでに稼働中のサイトを乗っ取ってしまう攻撃が実際に発生しています。
> 💬 *例えるなら：営業中の店舗のレジ横に「初期セットアップ用の設定ボタン」がむき出しのまま残っており、通りがかりの第三者がそれを押して店のオーナー登録を書き換えてしまうような状態です。*
{: .callout-danger}

| リスク度 | 影響を受ける人 | 悪用のされやすさ | まずやるべき対策 |
| :---: | :--- | :--- | :--- |
| 🔴 **緊急 (KEV)** | **Drupal Core `10.6.22` 未満、または `11.3.22` / `11.4.13` 未満の運用者** | 未認証の攻撃者が `install.php` へアクセスして実行可能（**実攻撃を確認済み**） | **修正版（`10.6.22` / `11.3.22` / `11.4.13`）へ即時更新し、`install.php` への外部アクセスを遮断** |

<details markdown="1">
<summary>🔍 技術的な仕組み・対象バージョン・対策コマンドを見る（エンジニア向け）</summary>

- **原因の仕組み**: Drupal Coreに同梱されるインストーラスクリプト（`core/install.php`）の制御不備により、特定の条件下で未認証の攻撃者が再インストール処理を強行し、任意コード実行（RCE）やサイト全体の乗っ取りを引き起こせる（アドバイザリ `SA-CORE-2026-017`）。2026年11月19日以降、実環境での積極的な悪用が確認されたため重要度が引き上げられ、**11月24日にCISAのKEV（悪用が確認されている脆弱性）カタログに追加**された（BOD 26-04に基づく米連邦機関の対応期限は **2026年11月27日**）。
- **対象バージョン**:
  - Drupal Core `< 10.6.22`
  - Drupal Core `>= 11.0.0` かつ `< 11.3.22`
  - Drupal Core `>= 11.4.0` かつ `< 11.4.13`
  - ※ Drupal 10.5.x以前および11.2.x以前はサポート終了（EOL）のため公式パッチは提供されない。
- **対策手順・コマンド**:
  ```bash
  # Composerを用いたDrupal Coreのアップデート例
  composer update "drupal/core-*" --with-all-dependencies
  drush updb -y && drush cr
  ```
  - 併せて、Webサーバー（NGINX / Apache）設定で `core/install.php` への外部からのアクセスをブロックすることが強く推奨されている。
- **一次ソース**: [Drupal Security Advisory - SA-CORE-2026-017](https://www.drupal.org/sa-core-2026-017) / [CISA KEV Catalog](https://www.cisa.gov/known-exploited-vulnerabilities-catalog)

</details>

### **Next.js — EdgeランタイムでHttpOnly Cookieが漏洩する脆弱性 (`GHSA-f3mh-rxg3-f5g2` / `CVE-2026-119346`)**

> **🔰 ひとことで言うと**
> 人気のWebフレームワークNext.jsの一部機能（Edge環境）で、本来ブラウザ側のプログラムから隠しておくべきログイン用の秘密データ（Cookie）が、応答ヘッダーに丸見えで出力されてしまう不具合が見つかりました。
> 💬 *例えるなら：銀行の窓口で「本人以外は見られない封筒」に入れたはずの暗証番号を、受付係がうっかり封筒の表側にも大きくメモして渡してしまうような状態です。*
{: .callout-danger}

| リスク度 | 影響を受ける人 | 悪用のされやすさ | まずやるべき対策 |
| :---: | :--- | :--- | :--- |
| 🟠 **中〜高 (CVSS ~6.0)** | **Next.js `15.x` / `16.x` でEdgeランタイム上のルートから `NextResponse` でCookieを設定している開発者** | 同一オリジン上で悪意あるJSが動作した場合に `HttpOnly` 属性を迂回して窃取可能 | **Next.jsを `15.5.29` または `16.4.5` 以上へアップデート** |

<details markdown="1">
<summary>🔍 技術的な仕組み・対象バージョン・対策コマンドを見る（エンジニア向け）</summary>

- **原因の仕組み**: App RouterのRoute HandlersやPages RouterのEdge API Routesなど、Edgeランタイム上で動作するルートにおいて `NextResponse` を用いてCookieを設定する際、フレームワーク内部用のレスポンスヘッダーである `x-middleware-set-cookie` が削除されず、公開レスポンスにそのまま含まれてしまう。このヘッダーにはCookieの値と属性が複製されているため、`HttpOnly` フラグによってJavaScriptからのアクセスを禁止していたセッショントークン等を、クライアント側のJavaScriptが読み取れてしまう。
- **対象バージョン**: `15.0.0` 〜 `15.5.28`、および `16.0.0` 〜 `16.4.4`。
- **対策手順・コマンド**:
  ```bash
  # 修正済みバージョンへのアップデート（例: 16.x系の場合）
  pnpm update next@16.4.5
  # 15.x系の場合
  pnpm update next@15.5.29
  ```
- **一次ソース**: [GitHub Security Advisory - GHSA-f3mh-rxg3-f5g2](https://github.com/vercel/next.js/security/advisories/GHSA-f3mh-rxg3-f5g2)

</details>

### **Node.js — TLS 1.2再ネゴシエーション時のクライアント証明書認証バイパス (`CVE-2026-123872`)**

> **🔰 ひとことで言うと**
> Node.jsの暗号化通信（TLS 1.2）で接続をやり直す際、接続先の名前をすり替えることで、本来は立ち入り禁止の別サーバー用エンドポイントへ認証を突破できてしまう弱点が見つかりました。
> 💬 *例えるなら：ビルの1階で一般エリアの入館証を見せたあと、エレベーターの中で「行き先は役員フロア」と申告し直すと、そのままセキュリティゲートを通過できてしまうような状態です。*
{: .callout-danger}

| リスク度 | 影響を受ける人 | 悪用のされやすさ | まずやるべき対策 |
| :---: | :--- | :--- | :--- |
| 🔴 **高 (CVSS ~8.1)** | **Node.js `22.x` / `24.x` / `26.x` でTLS 1.2およびクライアント証明書認証（mTLS）を利用する環境** | TLS 1.2の再ネゴシエーション中に `servername` を変更するだけで成立 | **Node.jsを `22.23.5` / `24.22.3` / `26.13.1` 以降へアップデート** |

<details markdown="1">
<summary>🔍 技術的な仕組み・対象バージョン・対策コマンドを見る（エンジニア向け）</summary>

- **原因の仕組み**: Node.jsのTLSモジュールにおいて、TLS 1.2の再ネゴシエーション（renegotiation）実行時にクライアント側が一方的に `servername`（SNI）を変更できる不備がある。これにより、あるホスト名に対して取得・検証済みのクライアント証明書認証状態を、より厳格なアクセス制御が敷かれた別の保護対象ホスト／エンドポイントへ引き継ぐ（認証バイパスする）ことが可能になる。
- **対象バージョン**: Node.js `22.x`（`22.23.5` 未満）、`24.x`（`24.22.3` 未満）、`26.x`（`26.13.1` 未満）。
- **対策手順・コマンド**:
  ```bash
  # Node.jsのバージョン確認と更新例（fnm / nvm等を利用している場合）
  node -v
  # 22.23.5 / 24.22.3 / 26.13.1 以降へ更新する
  ```
- **一次ソース**: [NVD - CVE-2026-123872](https://nvd.nist.gov/vuln/detail/CVE-2026-123872)

</details>

### **OpenAI × Cisco「Shirudo」— AI×eBPFでパッチ適用までの空白期間を無停止防御**

> **🔰 ひとことで言うと**
> 新しい脆弱性が見つかってから公式の修正パッチをテスト・適用するまでの「無防備な数日間」を埋めるため、AIが作った一時的な防御シールドを、サーバーを再起動せずにLinuxカーネルへ即座に組み込めるオープンソース基盤です。
> 💬 *例えるなら：水道管に亀裂が見つかったとき、大元の断水工事（パッチ適用）の準備が整うまでの間、自動で伸縮する特殊な止水バンドを水を出したまま巻き付けて水漏れを止めるような仕組みです。*
{: .callout-info}

| 比較ポイント | これまで (Before) | Shirudo 導入後 (After) |
| :--- | :--- | :--- |
| **脆弱性公開直後の対応** | 公式パッチの検証・再起動に数日〜数週間かかり、空白期間が無防備 | **AIが防御用eBPFシールドを生成し、再起動なしで即時ブロック** |
| **安全性と監査** | 暫定的なWAFルール等は設定ドリフトや誤検知の管理が煩雑 | **署名付き`.bee`パッケージ＋TPM 2.0監査＋公式パッチ適用で自動引退** |
| **実攻撃への耐性** | 未知の攻撃パターンへの微調整に手作業が必要 | **Java4Shell等の実攻撃を正常通信を止めずに遮断する実証に成功** |

```mermaid
flowchart LR
    A["脆弱性公開 (空白期間)"] -->|"1. AIが攻撃パターンを解析"| B["防御シールド生成 (.bee)"]
    B -->|"2. 署名・OCIレジストリ配信"| C["カーネルeBPF検証器"]
    C -->|"3. 再起動なしで即時ロード"| D["本番Linuxサーバー保護"]
    D -->|"4. TPM 2.0で監査・パッチ後自動解除"| E["公式パッチ適用完了"]
```

*図の見方：脆弱性が公開されてから公式パッチが適用されるまでの「空白期間」において、AI（Codex等）が生成し人間が承認・署名した防御シールド（`.bee`）を、LinuxカーネルのeBPF検証器を通して無停止で適用します。正式なパッチが当たるとシールドは自動的に解除されます。*

<details markdown="1">
<summary>🔍 技術的ブレークスルーとリリースノート詳細を見る</summary>

- **技術的ポイント**:
  - OpenAIとCiscoが2026年11月23日〜24日にかけて共同発表したOSSプロジェクト（名称は日本語の「シールド」に由来）。IsovalentのTetragonなどのLinux eBPF技術を基盤としている。
  - OpenAIのCodexなどのAIエージェントが脆弱性を調査して入力検証などのピンポイントな緩和策（upatches）を起案し、人間の承認・暗号署名を経て `.bee` パッケージとしてOCIレジストリ経由で配信される。
  - カーネルの封印済みキーリングとeBPFベリファイアで安全性を検証した上でロードされ、ハードウェアの **TPM 2.0** レジスタで適用・解除の履歴が改ざん不能な形で記録される。検証環境では、稼働中のElasticsearchに対する「Java4Shell」攻撃を正常トラフィックに影響を与えずブロックすることに成功した。
- **公式リンク**: [GitHub - shirudo-dev/shirudo](https://github.com/shirudo-dev/shirudo)

</details>

### **OpenAI「Pando」— 並列稼働するAIエージェントのGit遅延を80%削減するRust製バックエンド**

> **🔰 ひとことで言うと**
> 何千ものAIコーディングエージェントが一斉にコードを保存（プッシュ）しても渋滞が起きないよう、OpenAIがRustでゼロから作り直した超高速なGitサーバー基盤です。
> 💬 *例えるなら：1車線しかなく毎回全車両を止めて検問していた高速道路の料金所を、車線（ブランチ）ごとに独立した自動ETCゲートへ作り替えて渋滞を8割減らしたような仕組みです。*
{: .callout-info}

| 比較ポイント | 従来のGitサーバー (Before) | Pando (After) |
| :--- | :--- | :--- |
| **同時プッシュ時の制御** | リポジトリ全体で厳密な同期ロックが発生し待機が増大 | **ブランチ単位の独立更新（因果整合性）で数千の同時プッシュを処理** |
| **データ保存と配信** | 受信のたびに展開・再圧縮し、フェッチごとに動的生成 | **パックファイルを直接不変ストレージへ保存し、リージョンキャッシュで再利用** |
| **処理速度・スケール** | 高負荷時にモノレポの信頼性が90%未満に低下することも | **プッシュ遅延の中央値を約80%削減（約5倍高速化）、日次約1PBを処理** |

## **6. 📝 総評**

> **📌 今日の一言まとめ**
> AIエージェントが「コードを書く」段階から「インフラを無停止で守り、PC上で自律成長し、専用アプリとして常駐する」段階へと一気に拡張した一方、基盤ソフトウェア（VMware・Drupal・Node.js・Next.js）の足元を突く深刻な脆弱性への即応が問われる一日でした。
{: .callout-summary}

本日の動向から浮かび上がる最大のトレンドは、**「AIエージェントのためのインフラ再設計とローカル完結化」**です。OpenAIは、AIが本番Linuxの脆弱性を無停止で塞ぐ「Shirudo」と、数千のAIエージェントによる同時Gitプッシュを捌くRust製バックエンド「Pando」を立て続けに公開しました。さらにAnthropicは「Skills over MCP」によってツールのコンテキスト肥大化を構造的に解決し、「Install as app」でAIの成果物をOSネイティブの体験へと昇華させています。

一方で、ローカル環境側でも「Ternary Bonsai 2.5 27B（5.9GB）」や「Songe」のように、クラウドに頼らず手元のPCで完結・自己進化するエコシステムが急速に成熟しています。エンジニアとしては、こうした新基盤を積極的に検証しつつも、まずは **VMware（VMSA-2026-0011）** や **CISA KEV入りのDrupal（CVE-2026-132165）**、そしてEdge環境の **Next.js** や **Node.js** のパッチ適用を最優先で完了させることが不可欠です。

## **7. 📖 用語解説**

| 用語 | 解説 |
|------|------|
| **eBPF (Extended Berkeley Packet Filter)** | OSの心臓部（カーネル）を再起動や改造なしに、安全かつ高速に機能拡張できるLinuxの技術。警備員を建物の壁の中に後から追加配置するような仕組みです。 |
| **TPM 2.0 (Trusted Platform Module)** | パソコンやサーバーの基板上に搭載される暗号処理専用のセキュリティチップ。改ざんできない「金庫付きの記録帳」の役割を果たします。 |
| **CISA KEV (Known Exploited Vulnerabilities)** | 米国サイバーセキュリティ・社会基盤安全庁が公開する「すでに実際のサイバー攻撃で悪用が確認されている危険な弱点」の緊急リストです。 |
| **因果整合性 (Causal Consistency)** | 複数の作業が同時に進むシステムで、「原因と結果の順序」だけを守り、無関係な作業同士は待たせずに並列処理するデータ整合性の考え方です。 |
| **HttpOnly Cookie** | ログイン状態などを保つデータのうち、ブラウザ上のJavaScriptからは読み取れないよう鍵をかけた安全なCookieのこと。XSS攻撃による盗難を防ぎます。 |
| **3値量子化 (Ternary Quantization)** | AIモデルの重み数値を `-1`・`0`・`+1` の3通りだけに極限まで圧縮する技術。知能を保ったままメモリ消費量を劇的に減らせます。 |
| **LoRA (Low-Rank Adaptation)** | 巨大なAIモデル本体を丸ごと書き換えるのではなく、小さな追加パーツ（差分）だけを学習させてモデルを賢くする省エネな追加学習手法です。 |

*[TPM]: Trusted Platform Module（暗号鍵や監査ログを改ざんから守るハードウェアセキュリティチップ）
*[mTLS]: Mutual TLS（サーバーとクライアントの双方が証明書を提示して本人確認を行う相互TLS認証）
*[GA]: General Availability（ベータ版を経て一般向けに正式提供された状態）
*[EOL]: End of Life（公式のサポートおよびセキュリティ更新の提供終了）
*[OSS]: Open Source Software（ソースコードが公開され、自由に利用・改良できるソフトウェア）
*[SQLite]: ファイル1つで動作する軽量な組み込み型データベース
*[LoRA]: Low-Rank Adaptation（少ない計算資源でAIモデルを追加学習・調整する技術）
